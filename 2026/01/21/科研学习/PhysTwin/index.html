# 摘要与介绍

PhysTwin 将交互下的可变形物体的稀疏视频（三个摄像机视角）作为输入并重建一个可模拟的数字孪生体，具有完整的几何形状、高保真的外观和精确的物理参数

  • Under interaction (交互下)： 意思是视频里不仅有物体，还有人在戳它、捏它。这很重要，因为只有你捏它，电脑才能从变形中算出它有多软、多弹。

我们的方法主要包含两个关键组件：(1) 一种“物理感知”的表示方法，它结合了用于真实物理模拟的弹簧质点模型、用于几何结构的生成式形状模型，以及用于渲染图像的高斯泼溅（Gaussian Splats）技术；

以及 (2) 一个新颖的多阶段、基于优化的“逆向建模”框架，它能从视频中重建完整的几何形状、推断密集的物理属性，并复制逼真的外观。

输入一个稀疏的RGB-D视频序列，先根据额3D生成模型和视觉基础模型，前者还原出物体的基本结构（如果没拍全）后者推断出物体的运动和基本材质

由于某些物理参数（如与拓扑结构相关的属性）是不可微的，且高效优化它们并非易事，我们设计了一种分层的“从稀疏到密集”优化策略。该策略结合了零阶优化来处理不可微的拓扑结构和稀疏物理参数（例如碰撞参数和均匀弹簧刚度），同时采用一阶基于梯度的优化来精细调整密集的弹簧刚度并进一步优化碰撞参数。

# 相关工作

对于NeRF这些，或者D-NeRF，这些三维的重建做的很好，但是他们呢还是专注于重建物体的表面，并没有重建出物体的客观规律。（懂画画不懂物理说是🤣

还有的基于物理模拟器的，通常需要非常干净的观测数据，不能像PhysTwin拍几张稀疏的照片就能了事，而且还存在巴拉巴拉不能和现实拟合的一大堆问题。最接近自己的模型其实根本不符合物理规律，而且还要很多的相机视角，而且不能用（比如不能像PhysTwin一样用手捏这样的）。反正就是我的模型是真物理、真稀疏、真交互，你那个不行。

还有最后一派，因为还原物理规律太难了，于是选择不用物理规律来模拟，直接用AI进行还原，但是这个就导致他需要非常多的测试数据，并且这个模型只能限制于有限的特定环境中，相比之下我们的PhysTwin只要拍一段视频就好了。

基本的一个过程：

  1. 拍视频（左上）： 我们拍了一段人拉扯树懒的视频。

  2. 建初稿（左下）： 电脑里建立了一个初步的树懒模型，里面有弹簧骨架，外面有高斯皮肤。

  3. **做对比（右边）：**电脑先“模拟”拉一下这个虚拟树懒（下半部分）。然后跟视频里“真实”的树懒（上半部分）做对比。如果虚拟树懒弹回来的太慢，说明“弹簧太软了”。

  4. 改参数（红色箭头）： 电脑自动修改左下角的物理参数（变硬一点）。

    CgeometryC_{geometry}Cgeometry​：形状像不像？CmotionC_{motion}Cmotion​：动作轨迹对不对？CrenderC_{render}Crender​：画面颜色像不像？

  5. 循环： 重复这个过程，直到虚拟树懒的动作和画面跟视频里一模一样。

# 弹簧质点模型

预备知识：弹簧质点模型

一个可变形物体被表示为一组由弹簧连接的质量节点，形成一个图结构 G=(V,E)\mathcal{G} = (\mathcal{V}, \mathcal{E})G=(V,E)，其中 V\mathcal{V}V 是质点集合，E\mathcal{E}E 是弹簧集合。

每个质量节点 iii 都有一个位置 xi\mathbf{x}_ixi​（三维坐标）和一个速度 vi\mathbf{v}_ivi​（三维向量），它们随时间根据牛顿动力学进行演变。

（只有相邻的球才连接弹簧）这样整体就是一堆球和互相连接的弹簧成为一个巨大的整体。

作用在节点 iii 上的力是与其通过弹簧连接的相邻节点共同作用的结果：

核心公式：Fi=∑(i,j)∈EFi,jspring+Fi,jdashpot+Fiext\mathbf{F}_i = \sum_{(i,j)\in\mathcal{E}} \mathbf{F}_{i,j}^{\text{spring}} + \mathbf{F}_{i,j}^{\text{dashpot}} + \mathbf{F}_i^{\text{ext}}Fi​=∑(i,j)∈E​Fi,jspring​+Fi,jdashpot​+Fiext​

这个公式说的是：质点 iii 受到的总力，由三部分组成：

  1. 弹簧弹力 (Fi,jspring\mathbf{F}_{i,j}^{\text{spring}}Fi,jspring​)：所有连接到 iii 的邻居质点 jjj 通过弹簧对它施加的拉力或推力。$$ \mathbfF}_{i,j}({\text{spring)} = k_{ij} (|\mathbf{x}_j - \mathbf{x}i| - l) \frac{\mathbf{x}_j - \mathbf{x}_i}{|\mathbf{x}_j - \mathbf{x}_i|} $$。其中k就是弹簧的弹性系数，后面的表示弹性形变量，最后的表示方向向量。
  2. 阻尼力/缓冲力 (Fi,jdashpot\mathbf{F}_{i,j}^{\text{dashpot}}Fi,jdashpot​)：用来模拟能量损耗，防止弹簧无休止地震荡。$$ \mathbfF}_{i,j}({\text{dashpot)} = -\gamma (\mathbf{v}_i - \mathbf{v}_j) $$​。其中γ\gammaγ 是阻尼系数，后者表示相对速度，来模拟阻尼。如果没有这个系数，弹簧就会无休止的震荡，这显然不合理。
  3. 外力 (Fiext\mathbf{F}_i^{\text{ext}}Fiext​)：比如重力、风力或用户拽它的力。

当两个质点相距非常接近的时候，我们使用基于冲量的碰撞处理，包括物体自己质点的碰撞和物体和桌子的碰撞等等。

再对于位置更新：

\mathbf{v}_i^{t+1} = \delta \left( \mathbf{v}_i^t + \Delta t \frac{\mathbf{F}_i}{m_i} \right) $$用于更新速度，公式的含义显而易见，就是最外面要乘一层阻尼系数 $$ \mathbf{x}_i^{t+1} = \mathbf{x}_i^t + \Delta t \, \mathbf{v}_i^{t+1} $$更新位置，我们选用这个方程 > 由于计算机的时间是一段一段的，所以要使用这个 $\Delta t$ 来计算，另外选用新速度被成为半隐士欧拉（？比纯显式欧拉更加稳定。 最终我们汇总成动态模型：$\mathbf{X}_{t+1} = f_{\alpha, \mathcal{G}_0}(\mathbf{X}_t, a_t)$ 这里的 $\alpha$ 代表弹簧质点模型的所有物理参数，包括弹簧劲度、碰撞参数和阻尼，还包括手捏的一些物理参数（比如手在哪，有多大劲）后面我们的目标就是不断优化这个参数。 $\mathcal{G}_0$ 代表弹簧质点系统的“标准”几何和拓扑结构（也就是物体最开始没变形时的样子），$a_t$ 代表时刻 $t$ 的动作。 ## 方法 ### 问题格式化 首先对于输入来说，我们的输入格式为：$\mathbf{O}_{t,i} = (\mathbf{I}, \mathbf{D})$ 表示第 $t$ 秒，第 $i$ 个相机，他的输入的 $I$ 色彩图像和 $D$ 深度图 我们的核心目标是让这个最小：$$ \min_{\alpha, \mathcal{G}_0, \theta} \sum_{t,i} C(\hat{\mathbf{O}}_{t,i}, \mathbf{O}_{t,i}) $$，前者是电脑的预测值，后者是实际值 其中渲染规则：$\hat{\mathbf{O}}_{t,i} = g_\theta(\hat{\mathbf{X}}_{t,i})$ $g_{\theta}$把预测的 3D 状态投影回相机视角，再与真实相机图像对比 物理规则： $\hat{\mathbf{X}}_{t+1} = f_{\alpha, \mathcal{G}}(\hat{\mathbf{X}}_t, a_t)$ 这个函数就是上述提到的质点弹簧模型 其中： * **$\alpha$ (物理参数)：** 比如物体的质量、弹簧有多硬（刚度）、阻尼系数等。 * **$\mathcal{G}_0$ (几何与拓扑)：** 物体最开始长什么样，点与点之间是怎么连接的。 * **$\theta$ (外观参数)：** 高斯球的颜色、透明度、大小等渲染属性。 最终代价函数被分为三个分量：$C = C_{\text{geometry}} + C_{\text{motion}} + C_{\text{render}}$，分别捕捉 **3D几何**、**3D运动追踪** 以及 **渲染** 的差异。 ### 模型架构 然后就转化为了优化问题，我们要一阶段对模型的外观物理进行优化，二阶段对模型的外观进行优化。 #### 物理与几何优化 在第一阶段，我们考虑用如下公式优化： $$ \min_{\alpha, \mathcal{G}_0} \sum_{t} \left( C_{\text{geometry}}(\hat{\mathbf{X}}_t, \mathbf{X}_t) + C_{\text{motion}}(\hat{\mathbf{X}}_t, \mathbf{X}_t) \right)

其中 X^t+1=fα,G0(X^t,at)\hat{\mathbf{X}}_{t+1} = f_{\alpha, \mathcal{G}_0}(\hat{\mathbf{X}}_t, a_t)X^t+1​=fα,G0​​(X^t​,at​)

其中 CgeometryC_{\text{geometry}}Cgeometry​ 函数量化了部分观测点云 Xt\mathbf{X}_tXt​ 与推断状态 X^t\hat{\mathbf{X}}_tX^t​ 之间的单向倒角距离

一种算法，衡量集合到集合的匹配误差，计算公式为done-way(A→B)=1∣A∣∑a∈Amin⁡b∈B∥a−b∥2 d_{\text{one-way}}(A \rightarrow B) = \frac{1}{|A|} \sum_{a \in A} \min_{b \in B} \|a - b\|^2 done-way​(A→B)=∣A∣1​∑a∈A​minb∈B​∥a−b∥2，是因为观测点肯定要在预测点中出现，但是预测点不一定在观测点中出现（比如背面反过来）

CmotionC_{\text{motion}}Cmotion​ 描述的是追踪误差，就是观测到的和预测的运动是否一致，这里调用了一个 CoTracker3 的追踪算法

面临三个挑战：看不全，离散拓扑结构和物理参数联合优化，动态的模型的不连续性

所以我们把几何参数和其他参数分开处理，先获得完整的集合结构，然后从稀疏到密集来调整剩余的参数

# 生成形状

源于我们观测的本身不全，所以我们通过 3D 生成模型 TREL-LIS 生成一个完整的 3D 模型，作为一个先验的猜测。

为了提高质量，这里的过程是：用 Grounded-SAM2（目前最强的分割模型之一）把物体从背景里抠出来。用 Super-resolution（超分模型）把抠出来的图放大、变清晰。最后才丢给 TRELLIS 生成 3D 模型。

但是生成的形状可能在大小和姿态、形变等方面和原来的不一致，我们使用一个模块来修正它，首先通过使用 SuperGlue 匹配的 2D 对应点来估计初始旋转，然后使用 PnP（Perspective-n-Point） 算法进行细化。前者匹配对应的点，后者根据前者计算相机角度和位置。

这样使生成的 3D 模型尽可能和视频中的原物体重合。最后光线投射来确认正确性。

# 由稀疏到密集的优化策略

点弹簧模型既包含拓扑结构（即弹簧的连接方式），也包含定义在弹簧上的物理参数；

我们还引入了控制参数，用于连接 ‘控制点’ 和 ‘物体点’ 之间的弹簧，这些参数由一个半径和最大邻居数量来定义。（就是把手捏物体的点叫做控制点，然后如果在控制点一定半径内就把控制点和质点之间连上。

对于拓扑优化，同样的，我们也是通过连接半径和最大邻居数来控制的（启发式算法）

控制点提取：利用 Grounded-SAM2 来分割手部掩码，并利用 CoTracker3 来追踪手部运动。将这些点提升到 3D 后，我们应用最远点采样来获得最终的控制点集。

但是因为我们的弹簧数量这样的突变是不能求导的，然后局部可能由很多弹簧，很容易算错（局部最优）

所以我们用稀疏到密集的优化策略，先试错法，随机试几个半径，看看哪个模拟效果好（零阶优化）。这个阶段我们先假设物体是均质刚度的，即 kkk 是一个参数，第二阶段我们再采用一节梯度下降来进一步微调参数，这一阶段同时优化弹簧刚度和碰撞参数。

# 外观优化

每个高斯核由以下参数定义：3D 中心位置 μ\muμ、由四元数 q∈SO(3)q \in \mathbf{SO}(3)q∈SO(3) 表示的旋转矩阵、由 3D 向量 sss 表示的缩放矩阵、不透明度值 α\alphaα 以及颜色系数 ccc。

这应该是标准的 3D 高斯泼溅定义，即每个小球都有自己的位置（μ\muμ）、朝向（qqq）、大小（sss）、透明度（α\alphaα）和颜色（ccc）。这些参数统称为 θ\thetaθ。

我们通过 $$ \min_{\theta} \sum_{t,i} C_{\text{render}}(\hat{\mathbf{I}}{i,t}, \mathbf{I}) \quad \text{s.t.} \ \hat{\mathbf{I}}{i,t} = g\theta(\hat{\mathbf{X}}_t, i) $$ 来优化外观。

CrenderC_{\text{render}}Crender​ 计算渲染图像与真实图像之间的 L1\mathcal{L}_1L1​ 损失加上 D-SSIM 项。

  • L1\mathcal{L}_1L1​ Loss： 比较每个像素点的颜色差异（绝对值误差）。
  • D-SSIM： 比较图像的结构相似度（Structural Similarity）。这能保证图像看起来不模糊，结构清晰。

为了简单起见，我们只在第一帧优化外观。

虽然我们在第一帧就确定了参数，但是我们需要“皮肉跟着骨架运动”，我们采用了一种使用**线性混合蒙皮（Linear Blend Skinning, LBS）**的高斯更新算法，该算法利用邻近质点节点（mass nodes）的运动来插值 3D 高斯的运动。

  1. Mass Nodes（物理节点）： 是之前算出来的稀疏的质点，它们负责跑物理模拟。
  2. 3D Gaussians（高斯球）： 是负责显色的像素级微粒，数量很多。
  3. LBS（蒙皮）： 每个高斯球会寻找离自己最近的几个物理节点，并“绑定”在上面。
  4. 运动： 当物理节点移动时，它周围的高斯球会根据权重跟着一起移动、旋转。
