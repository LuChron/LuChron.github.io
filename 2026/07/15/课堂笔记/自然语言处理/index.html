# lecture 3 : embedding

上节课我们讲的就是最基本的MLP：

MLP（Multilayer Perceptron，多层感知机）**MLP 是一种最基础的神经网络模型。**它由多层神经元组成，通常包括：

  • 输入层（Input Layer）
  • 隐藏层（Hidden Layers）
  • 输出层（Output Layer）

每一层的神经元都会：

  1. 接收上一层的输入
  2. 做 加权求和 + 偏置
  3. 通过 激活函数（Activation Function）
  4. 输出到下一层

数学形式通常是：$$y = f(Wx + b)$$

MoE（Mixture of Experts，专家混合）：一种神经网络架构，在模型中设置多个“专家网络”（通常是多个 MLP），并通过一个 Router/Gating 根据输入选择 Top-k 个专家参与计算，而不是让所有专家都运行，从而实现 参数规模很大但实际计算量较小（稀疏激活）。它常用于大型 Transformer 模型中，用来替代普通 MLP 层，提高模型容量和效率。

# 词嵌入 : word embedding

首先什么是embedding呢，在数学是上一个低纬的东西嵌入到高纬的空间里。

# 流形假设

机器学习中的“流形假设（Manifold Assumption）”，是很多 降维、表示学习、生成模型 的基础思想。简要理解如下：

高维数据其实分布在一个低维的“流形”上。

虽然数据在 高维空间（比如图像是几千维像素），但真正变化的因素只有少数几个，因此数据实际上只占据高维空间中的一个 弯曲的低维结构（manifold）。

真实数据在高维空间中并不是随机分布，而是集中在一个低维流形上。

那么寻找这个流形空间的过程，就叫 embedding 嵌入

那我们怎么找到一个词的意思呢，最简单的方法就是去字典里面查这个意思。那么我们可以有一个知识库，里面记录了词语的关系，比如衡量大熊猫和小熊猫的距离，找他们共同的父节点。这就是传统的语义字典。

传统的词向量

one-hot 词表示的问题。传统的 NLP 方法把每个词看成一个独立的符号，并用 one-hot 向量表示：向量中只有一个位置是 1，其余都是 0，向量维度等于词表大小（可能从几万到几百万）。这种表示方式叫 localist representation，特点是维度很高且非常稀疏，而且不同词之间没有任何语义关系（例如 dog 和 cat 的向量同样完全不同）。因此这种离散表示存在效率和表达能力上的问题。

one-hot译作独热编码。最大的问题是词和词之间没有任何的关系。其实现在打模型的token也算是这个，不过在传入之后对向量进行修改了（让他们有联系）

# 模型概述

Word2Vec 的两种模型：CBOW 和 Skip-gram。

CBOW（Continuous Bag of Words）：
用上下文词预测中心词。例如已知周围词 w(t−2),w(t−1),w(t+1),w(t+2)w(t-2), w(t-1), w(t+1), w(t+2)w(t−2),w(t−1),w(t+1),w(t+2)，先把这些词的向量做 SUM/平均（projection），再预测中间的词 w(t)w(t)w(t)。

Skip-gram：
与 CBOW 相反，用中心词预测周围词。给定中心词 w(t)w(t)w(t)，模型去预测它周围的词 w(t−2),w(t−1),w(t+1),w(t+2)w(t-2), w(t-1), w(t+1), w(t+2)w(t−2),w(t−1),w(t+1),w(t+2)。

训练可视化：

大概是这样：

层 表示 维度
输入层 输入词（one-hot） V（就是one-hot纬度）
隐藏层 词向量（embedding），这就是我们最后想要的词向量 N（词向量纬度）
输出层 预测上下文中出现的词概率 V

但是现在词向量还有一些问题，比如一个词有好几种意思，但是我们只有一个词向量。另外这个是由无监督学习出来的，比较难DEBUG。

# Word2Vec 模型详解

首先，要建立一个最重要的认知：Word2Vec 本质上是一个“挂羊头卖狗肉”的模型。

它表面上的任务是“预测下一个词/上下文”，但实际上，我们根本不关心预测的结果，我们想要的是在这个预测过程中，神经网络被训练出来的“权重参数”（Weight）。 这层权重参数，就是我们要的词向量。

Word2Vec 采用的是一个非常简单的三层浅层神经网络。下面我们以 Skip-Gram（跳字模型：用中心词预测上下文） 为例，一层一层地拆解它的架构。

为了方便理解，我们设定两个具体数字：

  • VVV (Vocabulary) = 10,000（假设我们的词表里总共有 1 万个词）
  • NNN (Neurons/Dimension) = 300（假设我们想把词变成 300 维的向量）

# 输入层 (Input Layer)

在输入层，计算机依然只能接受最原始的表示方式：独热编码（One-Hot Vector）。

假设我们要输入的中心词是“苹果”，它是词表中的第 3 个词。
那么输入 xxx 就是一个 1×100001 \times 100001×10000 的行向量：
x=[0,0,1,0,0,…,0]x = [0, 0, 1, 0, 0, \dots, 0]x=[0,0,1,0,0,…,0]

# 输入层到隐藏层 (Hidden Layer) 及其权重矩阵 WWW

这是 Word2Vec 最核心的地方。输入层和隐藏层之间，有一个权重矩阵 WWW。

  • 矩阵 WWW 的维度是 V×NV \times NV×N，即 10000×30010000 \times 30010000×300。
  • 这个矩阵的每一行，就代表着词表里每一个词的 300 维向量！

【神奇的数学反应】
当我们将 1×100001 \times 100001×10000 的独热向量 xxx 与 10000×30010000 \times 30010000×300 的矩阵 WWW 相乘时，会发生什么？
数学上，用独热向量去乘一个矩阵，等价于直接把矩阵的对应行“抽”出来。
因为“苹果”在第 3 个位置，相乘的结果就是矩阵 WWW 的第 3 行。

这个抽出来的 1×3001 \times 3001×300 的向量，就进入了隐藏层，记为 hhh。

⚠️ 关键细节：
绝大多数神经网络的隐藏层都有激活函数（如 ReLU, Sigmoid）。但 Word2Vec 的隐藏层是线性的，没有激活函数！ 它仅仅做了一次矩阵乘法（查表操作）。

# 隐藏层到输出层 (Output Layer) 及其权重矩阵 W′W'W′

隐藏层现在有了一个 300 维的向量 hhh。接下来要用它去预测上下文词（比如预测“吃”）。

隐藏层到输出层之间，有另一个权重矩阵 W′W'W′。

  • 矩阵 W′W'W′ 的维度是 N×VN \times VN×V，即 300×10000300 \times 10000300×10000。
  • 它的每一列，可以看作是词表里每个词作为“上下文”时的向量表示。

我们将 1×3001 \times 3001×300 的向量 hhh，乘以 300×10000300 \times 10000300×10000 的矩阵 W′W'W′，就会得到一个新的 1×100001 \times 100001×10000 的向量，记为 uuu。
这个向量 uuu 里面的每一个数字，代表了词表里那 10000 个词可能出现在“苹果”周围的“得分”。

# Softmax 和损失计算 (Loss)

向量 uuu 里面的数字有正有负，不方便看作概率。所以我们要套用一个 Softmax 函数。
Softmax 的作用是把这 10000 个得分转换成 0 到 1 之间的概率值，并且让所有词的概率加起来等于 1。

输出的就是预测概率分布：y^=[0.001,0.05,0.0003,…,0.2,… ]\hat{y} = [0.001, 0.05, 0.0003, \dots, 0.2, \dots]y^​=[0.001,0.05,0.0003,…,0.2,…]

然后，我们将这个预测出来的概率分布，和真实的上下文词的独热编码（比如“吃”的独热编码）进行对比，计算交叉熵损失（Cross-Entropy Loss）。

交叉熵损失：

L=−∑iyilog⁡(y^i)L = - \sum_i y_i \log(\hat{y}_i) L=−i∑​yi​log(y^​i​)

注意，这个模型预测的是上下文中最可能出现的那个单词，所以 one‑hot 只有真实类那一项是 1：

L=−log⁡(y^true)L = - \log(\hat{y}_{\text{true}}) L=−log(y^​true​)

# 反向传播 (Backpropagation)

发现预测结果和实际结果有偏差后，神经网络通过反向传播算法，去更新两个矩阵 WWW 和 W′W'W′ 中的数字。
不断重复这个过程（喂入大量的文本数据），矩阵 WWW 和 W′W'W′ 中的数字就会不断被调整。

# 训练结束后

当模型训练完毕，输出层和矩阵 W′W'W′ 就可以直接扔掉了（它们只是用来辅助训练的工具）。

我们唯一保留的，就是输入层到隐藏层的权重矩阵 WWW。
这个 10000×30010000 \times 30010000×300 的矩阵，就是大名鼎鼎的 Word Embedding（词嵌入矩阵）。
你想要“苹果”的词向量？直接去矩阵 WWW 里把第 3 行拿出来，这就是蕴含了丰富语义的 300 维稠密向量了！

# CBOW 的架构

前面讲的是 Skip-Gram（1 个词预测多个词）。CBOW（多个词预测 1 个词） 的架构原理一模一样，只有隐藏层有一点点区别：

在 CBOW 中，输入是多个上下文词（比如“我”、“了”、“一个”的独热编码）。

  1. 这 3 个词通过矩阵 WWW，会抽取出 3 个 1×3001 \times 3001×300 的向量。
  2. 隐藏层的操作是：把这 3 个向量加起来，求一个平均值（Average），融合成一个唯一的 1×3001 \times 3001×300 向量 hhh。
  3. 然后再用这个融合后的 hhh，去乘以 W′W'W′ 预测中间的词（“吃”）。

循环神经网络如上：

RNN 用同一个函数 ( f ) 在时间序列上反复处理数据：
[
h_t, y_t = f(h_{t-1}, x_t)
]
组成：

  • 输入 ( x_t )：序列中的当前元素
  • 隐状态 ( h_t )：累计“记忆”（上下文信息）
  • 输出 ( y_t )：当前时刻的输出
  • 函数 ( f )：共享参数的网络（每一步都一样）
h0 + x1 → f → h1 → y1
h1 + x2 → f → h2 → y2
h2 + x3 → f → h3 → y3

就是每一步的状态来自于上一步的状态和当前的输出。

# 机器翻译

根据上节课的机器翻译encoder和decoder的内容，这个是怎么训练的：

在训练序列生成模型（如翻译、文本生成）时，我们会使用一种叫 "Teacher Forcing" 的策略，即用数据集中真实的正确序列作为每一步的输入来引导模型训练，同时通过计算模型预测概率与真实单词之间的差异来优化模型。

在以上训练差不多了的时候，我们选取其一部分自己生成的输出传递进去。

对于贪心算法，由于没有回头看的回溯机制，可能当前输出只是局部最优，但是对于整个句子来说不是最好的，然后一但前面的错了就无法改正。

为了弥补这一缺陷，集束搜索 (Beam search decoding) 应运而生。它是一种更优的搜索算法，核心思想是不再只保留一个最佳选择，而是在解码的每一步都保留 k 个最有可能的候选序列（这个 k 称为“集束宽度”或 beam size）。在下一步，它会基于这 k 个序列分别进行扩展，然后从所有新生成的序列中再次选出总概率最高的 k 个保留下来，淘汰其余的。这个过程就像用一束宽度为 k 的光束在所有可能的句子中探索，从而避免了因过早放弃某些有潜力的选项而导致的错误。

<img src="/assets/图片/image-20260331105945837.png" alt="image-20260331105945837" style="zoom: 67%;" />

  1. 大 k 值的好处与代价 (Larger k)
    • 好处：增大 k 意味着在每一步都会考虑更多的候选序列（hypotheses）。这有助于克服小 k 值的缺点，找到更优的、质量更高的句子。
    • 代价：k 越大，需要计算和存储的路径就越多，因此计算开销也越大（更慢，占用更多内存）。
  2. 大 k 值带来的新问题 (The Problems of Large k)这是最关键的一点：k 值并非越大越好，过大的 k 会引入新的问题。对于机器翻译（NMT）：研究发现，当 k 增大到一定程度后，翻译质量的评测指标（如 BLEU 分数）反而会下降。主要原因是，模型会倾向于找到概率极高但非常短的翻译结果。即使使用了长度惩罚等分数标准化方法，这个问题依然存在。因为模型很容易通过提前生成结束符来“偷懒”，得到一个概率很高的短句。对于开放式任务（如聊天机器人）：在像自由对话这样的任务中，过大的 k 会使模型倾向于生成非常通用、缺乏个性的回答（例如“我不知道”、“好的”等）。因为这些“安全牌”回答在训练数据中出现频率极高，所以它们的概率也很高，很容易在广泛的搜索中胜出。这牺牲了回答的多样性和趣味性。

# BLEU

BLEU（Bilingual Evaluation Understudy）是机器翻译的自动评估指标，核心是通过n-gram 与参考译文的重叠度来衡量译文质量。

核心原理：

  • 统计机器译文与参考译文的 n-gram（连续 n 个词）精确率
  • 加上短句惩罚（Brevity Penalty），避免过短译文虚高得分
  • 最终得分 = 各 n-gram 精确率几何平均 × 短句惩罚

示例计算：

  • 参考：Taro visited Hanako（3 词）
  • 系统：the Taro visited the Hanako（5 词）
  • 1-gram 精确率：3/5
  • 2-gram 精确率：1/4
  • 短句惩罚：min(1, 5/3) = 1.0
  • BLEU-2：√(3/5 × 1/4) × 1.0 ≈ 0.387

但是它还是有很多缺点的，比如不太适合处理差异过大的，没有语义连贯等等。

# METEOR

METEOR 是一种机器翻译自动评估指标，整体思路和 BLEU 类似，但做了更多优化。

核心改进：

  • 考虑同义改写（paraphrases）：允许用同义词 / 近义表达，更贴近人类语义判断
  • 考虑语序重排（reordering）：不严格要求词序和参考译文完全一致
  • 区分功能词 / 内容词：对实词（content word）匹配更敏感，更重视核心语义

优点：

  • 整体表现显著优于 BLEU
  • 尤其在高资源语言（如英语、中文等数据丰富的语言）上效果更好

缺点：

  • 对新语言需要额外资源支持（不过这些资源可自动生成）
  • 计算逻辑更复杂，实现成本比 BLEU 高

# Perplexity

Perplexity（困惑度）是语言模型质量的自动评估指标，用于衡量模型对未知文本的预测能力，无需实际生成文本。

核心定义

  • 计算 验证集（held-out set） 中单词的困惑度
  • 困惑度越低 → 模型对文本的预测越准确、越 “不困惑”

优点：

  • 天然解决 ** 多参考译文（multiple-reference）** 问题，适合存在多种正确表达的场景

缺点：

  • 不考虑解码过程或实际生成的输出，只反映模型的语言建模能力
  • 无法直接对应到生成文本的流畅度或语义准确性

# SMT

核心概念：

  • SMT (Statistical Machine Translation)：统计机器翻译，是2010年代前的主流机器翻译技术。

  • 目标：基于概率，寻找可能性最高的翻译结果。

工作原理 (核心公式)：

  • 最佳翻译 = argmax P(翻译模型) * P(语言模型)

  • 翻译模型 (Translation Model)：保证翻译的准确性。通过分析原文和译文的对应关系得出（例如，“chat” 对应 “cat” 的概率）。

  • 语言模型 (Language Model)：保证翻译结果的流畅性，使其读起来像一句通顺的话（例如，“the cat sat” 的概率比 “sat cat the” 高）。

关键依赖：

  • 平行语料库 (Parallel Corpus)：训练“翻译模型”的唯一原料。
  • 是什么：海量的人工翻译好的句对（如：英-法句对）。机器通过统计这些数据来学习翻译规律。

# 位置编码

对于自注意力机制来说，“狗咬人”和“人咬狗”计算出来的结果是一模一样的，因为它只看词与词之间的关系，不看词的位置。为了解决这个问题，就引入了位置编码。

<img src="/assets/图片/image-20260407115031017.png" alt="image-20260407115031017" style="zoom:50%;" />

看右上角那个小流程图，它展示了实际在模型中发生的事情：

  1. xix^ixi：输入的一个词（比如“我”）。
  2. aia^iai：这个词通过查表得到的词向量（Word Embedding），代表这个词的“语义（意思）”。
  3. eie^iei：这个位置对应的位置向量（Positional Encoding），代表这个词在句子中的“位置”。
  4. ei+aie^i + a^iei+ai：将词的意思和位置直接“加”在一起。 （这是很多初学者困惑的地方：为什么语义和位置可以强行相加？下半部分就是要证明这一点）。
  5. 加完之后混合了“语义+位置”的新向量，再去生成上一张图里的 q,k,vq, k, vq,k,v。

数学原理解释：

  1. 拼接（Concatenation）：
    看中间蓝色的 xix^ixi 和灰色的 pip^ipi。
  • xix^ixi 是输入的词。
  • pip^ipi 是表示位置的独热向量（One-hot vector）。看左下角，如果这是句子的第 iii 个词，那么这个长条向量的第 iii 个位置是 1，其他全是 0。
  • 现在把 xix^ixi 和 pip^ipi 上下拼成一个更长的大向量： [xipi]\begin{bmatrix} x^i \\ p^i \end{bmatrix}[xipi​]
  1. 乘以权重矩阵运算：
    为了把这个大向量转换成我们要的特征，需要乘一个大的黄色矩阵 WWW。
    这个大矩阵 WWW 被中间一条虚线劈成了两半：
  • 左半边叫 WIW^IWI (用来处理输入 Input 的权重)
  • 右半边叫 WPW^PWP (用来处理位置 Position 的权重)
  1. 数学等价转换（最右侧的两个黑框）：
    根据矩阵乘法的规则，用大矩阵乘以拼接后的大向量，等价于把它们分开乘然后再加起来：

[WI ∣ WP]×[xipi]=WI×xi + WP×pi[W^I \ | \ W^P] \times \begin{bmatrix} x^i \\ p^i \end{bmatrix} = W^I \times x^i \ \mathbf{+} \ W^P \times p^i [WI ∣ WP]×[xipi​]=WI×xi + WP×pi

  1. 对应回原来的概念：
  • 图中写明了：WI×xiW^I \times x^iWI×xi 其实就是 aia^iai（普通的词向量）。
  • 图中写明了：WP×piW^P \times p^iWP×pi 其实就是 eie^iei（位置向量）。为什么？因为 pip^ipi 只有一个位置是 1，其他全是 0。根据矩阵乘法，WPW^PWP 乘以它，其实就是把 WPW^PWP 矩阵的第 iii 列单独“抽”了出来，那一列就是位置向量 eie^iei。
  • 所以，最后的结果变成了 ai+eia^i + e^iai+ei。

# Add & Norm层

它实际上由两个独立的操作组成：残差连接（Add） 和 层归一化（Layer Normalization, Norm）。这两个操作协同工作，极大地提升了 Transformer 的训练稳定性、收敛速度和最终性能。

（1）残差连接（Add）

目的： 解决深层神经网络中普遍存在的梯度消失/爆炸问题，并促进信息的直接流动。

操作： 将子层（自注意力层或 FFN）的输入直接加到该子层的输出上。

公式：OutputAdd=SublayerInput+SublayerOutput(SublayerInput)Output_{Add} = Sublayer_{Input} + Sublayer_{Output}(Sublayer_{Input})OutputAdd​=SublayerInput​+SublayerOutput​(SublayerInput​)

其中 SublayerOutput(SublayerInput)Sublayer_{Output}(Sublayer_{Input})SublayerOutput​(SublayerInput​) 代表自注意力或 FFN（Feed Forward Network） 对输入进行计算后产生的结果。

直观理解： 想象一下学习一项新技能（子层要学习的新变换）。残差连接允许模型先保留已经掌握的旧技能（原始输入），然后在这个基础上只学习需要做出的增量调整或修正（子层输出的变化量）。这样，即使新学的调整很小或者学习过程遇到困难，至少旧技能（原始信息）也能完整无损地传递下去。

层归一化（Layer Normalization, Norm）

Layer Normalization（LN）用于稳定训练过程并加速收敛，其核心思想是减少内部协变量偏移（Internal Covariate Shift），即减小同一层中不同特征维度激活值分布的变化。

对单个样本在所有特征维度上进行归一化。

首先计算均值与标准差：

μ=1d∑i=1dxi\mu = \frac{1}{d} \sum_{i=1}^{d} x_i μ=d1​i=1∑d​xi​

σ=1d∑i=1d(xi−μ)2\sigma = \sqrt{\frac{1}{d} \sum_{i=1}^{d} (x_i - \mu)^2} σ=d1​i=1∑d​(xi​−μ)2​

然后进行标准化：

x^i=xi−μσ2+ϵ\hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \epsilon}} x^i​=σ2+ϵ​xi​−μ​

最后引入可学习参数进行线性变换：

yi=γx^i+βy_i = \gamma \hat{x}_i + \beta yi​=γx^i​+β

其中，γ\gammaγ 和 β\betaβ 为可学习参数，ϵ\epsilonϵ 为防止除零的小常数。

为什么 Layer Norm 更适合 Transformer/RNN？

Batch Normalization（BN）是在一个 batch 内，对单个特征维度在所有样本上进行归一化；而 Layer Normalization 是在单个样本内部，对所有特征维度进行归一化。因此，LN 不依赖 batch size，而 BN 对 batch size 较为敏感。

LayerNorm 在序列模型中的优势

LayerNorm 不依赖 batch size，在小 batch 或 batch=1 时仍然稳定；同时它在每个样本内部独立计算统计量，能够自然适应变长序列；此外，其归一化过程在不同时间步之间相互独立，更符合 RNN 和 Transformer 的时序建模特点。

Add & Norm 结构

在 Transformer 中，子层通常采用如下结构：

Output=LayerNorm(x+Sublayer(x))\text{Output} = \text{LayerNorm}(x + \text{Sublayer}(x)) Output=LayerNorm(x+Sublayer(x))

其中，xxx 为输入，Sublayer(x)\text{Sublayer}(x)Sublayer(x) 表示子层（如自注意力或前馈网络）。

残差连接 x+Sublayer(x)x + \text{Sublayer}(x)x+Sublayer(x) 保留了原始输入信息，同时为梯度提供直接传播路径，有助于缓解梯度消失问题。LayerNorm 对该结果进行归一化，使其分布更加稳定，从而加速训练收敛。

Transformer 中存在两种常见形式：

# Feed Forward Network

位置与作用

FFN 位于每个 Transformer 编码器层和解码器层内部，通常紧跟在 Add & Norm 之后，用于对自注意力层的输出进行进一步变换。

其核心作用是引入非线性，并对每个位置的表示进行独立的特征变换。

主要特点

FFN 对序列中的每个位置（token）独立地应用相同的变换，即 position-wise 结构。因此，其计算不依赖其他位置，可以并行执行。

与自注意力不同，FFN 不建模不同位置之间的关系，而是专注于单个位置内部的特征变换与表达能力提升。

结构形式

标准 FFN 由两层线性变换和一个非线性激活函数组成：

FFN(x)=σ(xW1+b1)W2+b2\text{FFN}(x) = \sigma(x W_1 + b_1) W_2 + b_2 FFN(x)=σ(xW1​+b1​)W2​+b2​

其中：

  • W1,W2W_1, W_2W1​,W2​ 为权重矩阵
  • b1,b2b_1, b_2b1​,b2​ 为偏置项
  • σ(⋅)\sigma(\cdot)σ(⋅) 为激活函数（如 ReLU、GELU）

在原始论文中，常用 ReLU：

FFN(x)=max⁡(0,xW1+b1)W2+b2\text{FFN}(x) = \max(0, x W_1 + b_1) W_2 + b_2 FFN(x)=max(0,xW1​+b1​)W2​+b2​

维度变化

FFN 通常采用“先升维再降维”的结构：

dmodel→dff→dmodeld_{\text{model}} \rightarrow d_{\text{ff}} \rightarrow d_{\text{model}} dmodel​→dff​→dmodel​

这种结构使模型能够在更高维空间中进行特征变换，从而提升表达能力。

与自注意力的关系

自注意力层负责建模序列中不同位置之间的依赖关系；FFN 则对每个位置的表示进行独立的非线性变换。二者相互配合，共同构成 Transformer 的核心计算单元。

# Decoder 结构

Transformer 的 Decoder block 结构，与 Encoder block 相似，但是存在一些区别：

# Cross-Attention

对于我之前的疑惑：

Multi-Head Attention 是一个通用模块。它是否是 Cross-Attention，不取决于类名，而取决于传入的 Q、K、V 来自哪里。

  • 如果 Q = K = V = 解码器自己的输入 → Self-Attention
  • 如果 Q = 解码器，K = V = 编码器输出 → Cross-Attention

所以：

同一个 MultiHeadAttention 类，传不同的 Q/K/V，就变成不同类型的注意力。

位置

在 Transformer 解码器的每一层中：

[
\text{Masked Multi-Head Self-Attention} \rightarrow \text{Add & Norm} \rightarrow \text{Cross-Attention} \rightarrow \text{FFN}
]

即 Cross-Attention 是第二个 Multi-Head Attention。

核心目的

Cross-Attention 的作用是：在生成目标序列的当前词时，让解码器有选择地关注编码器输出的整个源序列表示。

这是 Seq2Seq 任务（如机器翻译、文本摘要等）的核心机制。

直观理解

想象你在翻译一句话。当你在写目标语言的某个词时，你需要参考源语言句子的哪些部分提供了最相关的信息？Cross-Attention 就是让解码器模型自动学习这种“软对齐”（Soft Alignment）的过程。它动态地为每个目标词位置计算一个权重分布，这个分布告诉模型源序列的哪些词或短语对生成当前目标词最重要。

输入来源

Cross-Attention 接收两部分输入：

(1) Query（Q）：来自解码器

  • 来源：

[
Q = \text{Decoder Output (after Multi-Head Self-Attention + Add & Norm)}
]

  • 含义：表示当前解码状态（包含已生成信息 + 当前预测位置）

  • 形状：

[
Q \in \mathbbR}({B \times T_{\text{target)} \times d_{\text{model}}}
]

(2) Key（K）与 Value（V）：来自编码器

  • 来源：

[
K, V = \text{Encoder Output (final layer)}
]

  • 含义：

表示编码器对整个源序列的理解

  • 形状：

[

# 预训练

预训练（Pre-training）本质上是：先在大规模通用数据上训练一个模型，让它学到“通用能力”，再拿去做具体任务。

直觉上可以理解为：不是让模型一开始就学“某个任务”，而是先让它“变聪明”。

从过程上看，预训练通常分两步：第一步是通用训练（预训练阶段）
模型在海量数据上学习，比如：

  • 文本 → 学语言规律（语法、常识、逻辑）
  • 图像 → 学边缘、纹理、结构
  • 多模态 → 学图文对应关系

例如大语言模型常用的是：预测下一个词（next token prediction）

本质是让模型学会：“在当前上下文下，什么是合理的内容”

第二步是任务适配（微调 / 使用阶段）

有两种常见方式：

  • Fine-tuning（微调）：在小数据上再训练，让模型适应任务
  • Prompt / In-context：不改模型，直接通过输入引导它完成任务

最经典的预训练其实就是我们的词向量。预训练的第一步是：把词变成向量（embedding），本质就是一个训练好的查表过程。

# BERT

BERT 的全称是 Bidirectional Encoder Representations from Transformers。
它是 Google 在 2018 年提出的一种自然语言处理（NLP）模型。它的出现可以说是 NLP 领域的“原子弹”，打破了当时几乎所有的各项纪录。

我们可以把它的名字拆解：

  • T (Transformers): 它的底层身体结构是 Transformer，准确地说，它只用了 Transformer 架构中的 Encoder（编码器） 部分。
  • ER (Encoder Representations): 它的主要工作不是像 ChatGPT 那样“聊天/生成文字”，而是去**“深刻理解”一句话的含义，并把它转化成计算机能懂的高级特征向量（Representations）。可以理解成一个极其优秀的“文本阅读理解专家”**。
  • B (Bidirectional - 双向的): 这是 BERT 最牛、最核心的特点。
    • 以前的模型（单向）： 只能从左读到右。比如读“苹果”这个词，它只能看到前面的词。
    • BERT（双向）： 它是一眼看全一句话，**同时结合上下文（左边和右边）**来理解当前的词。
    • 举个例子： “我昨天买了一个苹果手机” 和 “我昨天吃了一个苹果”。
    • 如果是单向阅读，读到“苹果”时，前面都是“我昨天...了一个”，模型根本不知道“苹果”是水果还是手机。但 BERT 能同时看到后面的“手机”或“句号”，瞬间就能精准区分这两个“苹果”的含义。

# MLM

MLM 的全称是 Masked Language Modeling，中文叫 掩蔽语言模型。
它不是一个独立的模型，而是 专门为了训练 BERT 发明的一种“学习方法”或“考试题型”。

为什么需要 MLM

以前训练语言模型（比如 GPT 的祖先），都是用“接龙”的方法：给定前几个词，让模型猜下一个词。
但是，BERT 是“双向”的，它能一眼看到整句话。如果还让它猜下一个词，这就好比你让学生做填空题，却把带答案的完整试卷直接发给他，他直接“抄答案”（通过网络结构直接看到后面的词）就行了，什么都学不到。

MLM 是怎么做的

为了不让 BERT 抄答案，又能逼迫它利用双向信息学习，Google 的科学家想出了一个极其简单又绝妙的方法：做完形填空。

这就是你在上一张图里看到的：在把一句话输入给 BERT 之前，人为地随机抠掉（Mask）句子中 15% 的词。
然后对 BERT 说：“我不限制你怎么看上下文，但现在卷子上有几个洞，你根据剩下的词，把这些洞里的词给我猜出来！”

  • 比如原句： 今天 天气 真好，我们 去 爬山 吧。
  • MLM 破坏后： 今天 [MASK] 真好，我们 [MASK] 爬山 吧。

BERT 为了猜出第一个 [MASK] 是“天气”，它不仅要看左边的“今天”，还要看右边的“真好”，这就强迫它必须同时理解左右两边的上下文。

MLM 的处理小细节

为了防止 BERT 在实际应用时犯傻（因为实际生活中没人在句子里加 [MASK]），这 15% 挑出来的词会做三种处理：

  • 80% 抠掉： 换成 [MASK]（完形填空）。
  • 10% 乱填： 换成随机的词，比如把“天气”换成“苹果”（故意加入错别字，逼迫模型纠错并更依赖上下文）。
  • 10% 不动： 保持原词不变（让模型知道，给你的词有时候也是对的，你要坚定自己的判断）。

# Linear Attention

标准 Transformer 的 self-attention 需要计算完整的注意力矩阵：

[
\textAttention}(Q,K,V)=\text{softmax}\left(\frac{QK(\top){\sqrt{d}}\right)V
]

如果序列长度是 (N)，注意力矩阵大小是 (N\times N)，所以显存和计算都会随序列长度快速增长，典型复杂度是 (O(N^2))。

Linear Attention 的核心想法：把 self-attention 中最贵的部分改写成可以按序列递推 / 累积的形式，从而避免显式保存完整的 (N\times N) 注意力矩阵。

PPT 里给的直觉是：

  • Linear Attention = Self-Attention without Softmax
  • Linear Attention = RNN without forget gate

也就是说，它一方面像 attention 一样做信息聚合，另一方面又可以像 RNN 一样维护一个“历史状态”。这样训练时能更并行，推理时也可以逐 token 更新状态。

但是 Linear Attention 有一个问题：它不容易忘记旧信息。

标准 attention 里的 softmax 会重新分配注意力权重，重要 token 权重大，不重要 token 权重小；而线性形式如果只是不断累积，历史信息会一直留在状态里，模型不一定能很好地区分“该保留的”和“该淡化的”。

# Retention Network

Retention Network（RetNet）可以理解成对 Linear Attention 的进一步改造。

它的目标是同时保留三件事：

  • 训练时可以并行。
  • 推理时可以像 RNN 一样递推。
  • 长序列上比普通 attention 更省显存。

PPT 中强调了 forget / keep / fade 这类机制：也就是让模型不仅能保存历史，还能控制哪些信息要保留、哪些信息要衰减。

Gated Retention Network 进一步加入 gate，让模型动态控制信息流。直觉上类似 LSTM/GRU 里的门控思想，只是这里服务的是 attention/retention 风格的序列建模。

和 Transformer 对比：

方法 主要思想 优点 风险
Transformer Attention 显式计算所有 token 两两关系 表达能力强，可解释性强 长序列 (O(N^2)) 显存压力大
Linear Attention 去掉/改写 softmax，让注意力可线性计算 更省显存，适合长序列 容易“不会忘”
RetNet / Gated Retention 在线性状态中加入 retention/gate 兼顾并行训练和递推推理 结构更复杂

# Contextualized Word Embedding

传统 Word2Vec / GloVe 的问题是：同一个 token 永远查到同一个 embedding。

例如：

  • 宠物狗 里的“狗”
  • 单身狗 里的“狗”

如果只做表查找，两个“狗”的向量是一样的。但这两个词里的语义明显不同。

所以后来的预训练模型使用 Contextualized Word Embedding（上下文化词向量）：

token 的表示不只由 token 本身决定，还由上下文决定。

也就是说，同一个词放在不同句子里，经过 LSTM / Transformer / Tree-based model 等多层模型以后，会得到不同的上下文化表示。

这也是 BERT、GPT 这类模型比静态词向量强很多的原因：它们输出的不是一个死的查表向量，而是“结合上下文读完以后”的向量。

# Bigger Model 和 Smaller Model

预训练模型的发展有两个方向：

1. Bigger Model

把模型做大：更多层、更宽 hidden size、更多参数、更多数据。比如 Megatron、Turing NLG 这类工作。

大模型的优势是容量更大，能记住和抽象更多模式；缺点是训练和部署成本非常高。

2. Smaller Model

把模型压小，让它更容易部署。常见路线包括：

  • Network Pruning（剪枝）：删掉不重要的连接、神经元或结构。
  • Knowledge Distillation（知识蒸馏）：用大模型当 teacher，训练小模型 student。
  • Parameter Quantization（参数量化）：用更低 bit 表示权重，比如 fp16、int8、int4。
  • Architecture Design（结构设计）：直接设计更轻量的模型结构。

这部分只是引出“模型太大怎么办”，真正的模型压缩会在第 7 个 PPT 里继续讲。

# Fine-tuning

预训练模型学到的是通用语言能力，下游任务还需要 fine-tune。

基本做法：

  1. 输入句子或句子对。
  2. 经过预训练模型得到表示。
  3. 接一个 task-specific layer。
  4. 用具体任务的数据继续训练。

输入可以是：

  • one sentence：单句分类、情感分析等。
  • multiple sentences：句子对匹配、自然语言推理、问答中的 query-document 等。

输出常见有四类：

输出类型 例子 做法
one class 情感分类、文本分类 用 [CLS] 的表示接分类器
class for each token 命名实体识别、词性标注 每个 token 输出一个类别
copy from input 抽取式 QA 预测答案 span 的起点 (s) 和终点 (e)
general sequence 翻译、摘要、生成 接 decoder 或直接做 seq2seq

# 抽取式 QA

输入：

  • Document: (D=d_1,d_2,\cdots,d_N)
  • Query: (Q=q_1,q_2,\cdots,q_M)

输出两个整数：

[
(s,e)
]

答案就是：

[
A=d_s,\cdots,d_e
]

BERT 做抽取式 QA 时，通常把 question 和 document 拼起来：

[CLS] question [SEP] document

然后对 document 中每个位置分别预测：

  • 这个位置是不是答案起点。
  • 这个位置是不是答案终点。

最后选出概率最大的 (s,e)。

# Fine-tune 的几种方式

1. 全量 fine-tune

所有参数都跟着下游任务更新。

优点：效果通常最好。

缺点：每个任务都要保存一份大模型参数，显存和存储压力大。

2. Feature extractor

把预训练模型固定住，只把它当特征提取器，然后训练一个小的 task-specific layer。

优点：省显存，训练快。

缺点：适配能力弱一些。

3. Adapter

在每层 Transformer 中插入很小的 Adapter 模块，只训练 Adapter 和任务头，原模型主体参数固定。

优点：每个任务只存一小份 Adapter。

缺点：结构会稍微复杂一点。

4. Weighted Features

不同层的表示可能包含不同信息。可以学习每一层的权重，把多层 hidden states 加权融合后用于下游任务。

# Self-supervised Learning

预训练语言模型通常不依赖人工标注，而是用 self-supervised learning（自监督学习）。

监督学习是：

[
x \rightarrow y
]

也就是输入 (x)，人工给标签 (y)。

自监督学习是：

[
x \rightarrow x'
]

标签来自数据本身。比如从一段文本里挖掉一部分，让模型预测被挖掉的词；或者给前面的 token，让模型预测下一个 token。

NLP 中最典型的两种自监督任务：

  • Masked Language Modeling（MLM）：BERT 风格，mask 中间的词，再用左右上下文预测。
  • Next Token Prediction：GPT 风格，给定左侧上下文，预测下一个 token。

# GPT 的 Next Token Prediction

GPT 类模型训练时做的是语言模型任务：

[
P(w_{t+1}\mid w_1,\cdots,w_t)
]

也就是从左到右读文本，根据当前上下文预测下一个 token。

训练过程：

  1. 输入序列 (w_1,w_2,w_3,\cdots)。
  2. 每个位置输出一个 hidden state (h_t)。
  3. 用线性层 + softmax 得到词表上的概率分布。
  4. 用 cross entropy 让模型预测真实的下一个 token (w_{t+1})。

这和之前 RNN-LM 的训练目标本质一样，只是 GPT 用的是带 causal mask 的 Transformer Decoder。

GPT 的 self-attention 有限制：当前位置只能看左边和自己，不能偷看未来 token。

所以：

  • BERT：双向 encoder，更适合理解任务。
  • GPT：单向/因果 decoder，更适合生成任务。

# ELMo 和双向语言模型

PPT 里还提到 ELMo。

ELMo 使用的是 bidirectional LSTM：

  • 一个 LSTM 从左往右读。
  • 一个 LSTM 从右往左读。

这样每个词的表示同时包含左上下文和右上下文。

它解决的问题是：只做 next token prediction 时，模型看到的是左上下文；但理解一个词，右上下文也很重要。

这和 BERT 的动机类似：都希望得到上下文化表示。但技术路线不同：

  • ELMo：BiLSTM。
  • BERT：Transformer Encoder + MLM。
  • GPT：Transformer Decoder + Next Token Prediction。

# LLM 训练需要多少显存

假设是一个 8B 参数模型。

如果参数用 fp32：

[
8B \times 4\text{ bytes}=32\text{GB}
]

训练时为了加速，一般 GPU 上会用 fp16/bf16 参与计算，所以模型权重本身可以是：

[
8B \times 2\text{ bytes}=16\text{GB}
]

但训练不只有权重，还要保存：

  • fp16/bf16 model weights：约 16GB。
  • gradients：约 16GB。
  • Adam optimizer 的 momentum：约 32GB。
  • Adam optimizer 的 variance：约 32GB。
  • fp32 master weights / optimizer 相关状态：PPT 中整体算下来约 128GB 级别。

PPT 的结论是：只看一个 8B 模型，参数、梯度、Adam 状态加起来就可能到 128GB 左右，还没算 activations 和输入。

对比常见 GPU：

  • T4：约 15GB。
  • 4090：约 24GB。
  • A100：约 40GB。
  • H100：约 80GB。

所以单卡训练完整 LLM 很快就不现实。

# Activations

训练时 forward 过程中会保存中间结果，backward 时要用它们算梯度。这些中间结果就是 activations。

长上下文下 activations 会非常大，尤其是 attention。

PPT 中的例子：

  • batch size = 1。
  • context 可以从 256 tokens 到 16k tokens。
  • 32 层模型。
  • 单层 attention activation 可能到 40GB 级别。
  • 单层 feed forward activation 约 2.2GB。
  • 32 层累积后可能到 TB 级别，PPT 图里给出约 1.35TB。

这说明：训练 LLM 时，显存瓶颈不只是模型参数，长序列的 activations 也非常关键。

# Activation recomputation / Gradient checkpointing

解决 activation 太大的常见方法是 activation recomputation，也叫 gradient checkpointing。

核心思想：

  • forward 时不保存所有 activations。
  • 只保存一些关键 checkpoint。
  • backward 需要某段中间结果时，再重新算一遍。

优点：显著省显存。

缺点：需要重复计算，所以训练会变慢。

# Batch Size 和 Gradient Accumulation

大模型训练需要足够大的 batch size，才能得到比较稳定的梯度。

PPT 给的经验范围：

  • 一般是 4M 到 60M tokens per batch。
  • DeepSeek V3 例子：batch size 1920，context length 32K，总 token 数约 61M。

如果单次 mini-batch 放不下，可以用 gradient accumulation（梯度累积）。

公式：

[
\text{Global batch size}=\text{mini batch size}\times\text{gradient accumulation steps}
]

例如：

[
1920=16\times 120
]

意思是每次只跑 mini batch = 16，连续累积 120 次梯度以后，再做一次 optimizer step。

# DeepSpeed ZeRO

ZeRO 的全称是 Zero Redundancy Optimizer。

它要解决的问题是：数据并行时，每张 GPU 都保存一整份模型参数、梯度和 optimizer states，这会造成大量重复。

ZeRO 的思想是：把这些状态切分到多张 GPU 上，每张 GPU 只保存一部分，需要时再通信拿到对应部分。

PPT 中分为三个阶段：

阶段 切分什么 显存节省
ZeRO-1 optimizer states 先减少 Adam 状态冗余
ZeRO-2 optimizer states + gradients 再减少梯度冗余
ZeRO-3 optimizer states + gradients + parameters 连模型参数也切分

ZeRO-3 最省显存，但通信更多。

PPT 中还强调训练速度取决于：

  • 网络带宽。
  • 模型大小。
  • 硬件配置。

一般不会慢一个数量级，但通信开销一定存在。PPT 图里还提到 NVLink 约 900GB/s，意思是高速互联对 ZeRO 很重要。

# ZeRO-Offload

ZeRO-Offload 是把一部分状态从 GPU 挪到 CPU 内存。

可以 offload 的对象包括：

  • optimizer states。
  • model parameters。

这样能大幅减少 GPU 显存占用，但 CPU 和 GPU 之间传输数据会很慢。

PPT 里明确警告：

using offload can be very slow

所以 Offload 更像是“显存不够时的救命方案”，不是默认的高性能方案。

PPT 图中的直观结论：

  • offload 后每张 GPU 显存可以降到很低。
  • 但 step time 可能明显变长。
  • 不 offload 时速度更快，但需要更多 GPU 显存。

# Kernel

大模型训练中，很多耗时来自底层算子。

PPT 按抽象层次列了几种实现方式：

Naive PyTorch
torch.compile()
Triton
CUDA

越往上，代码越容易写，但控制更少、速度可能较慢。

越往下，越接近硬件，控制更强、速度更快，但开发难度更高。

所以工程上会用 optimized kernel 来替换一些核心计算，比如 attention、RMSNorm、cross entropy 等。

# FlashAttention

FlashAttention 解决的是 attention 的速度和显存问题。

它计算的数学结果和标准 scaled dot-product attention 一样，但实现方式更聪明。

普通 attention 会显式生成很大的 (N\times N) attention matrix：

  • MatMul。
  • Scale。
  • Mask。
  • Softmax。
  • Dropout。
  • MatMul with V。

这些步骤会产生大量中间张量，显存压力大。

FlashAttention 的做法：

  • 使用 fused kernel，把多个步骤合并。
  • 分块读取 Q、K、V。
  • 尽量减少 GPU HBM 和 SRAM/缓存之间的数据搬运。
  • 不完整保存 (N\times N) 注意力矩阵。

结果：

  • 训练更快。
  • 显存更少。
  • 长序列收益更明显。

PPT 中给的直觉是：普通 attention 空间接近 (O(N^2))，FlashAttention 通过优化访存使显存更接近线性。

# Liger Kernel

Liger Kernel 是用 Triton 重新实现一些 LLM 核心计算。

目标：

  • 提高吞吐量。
  • 降低 peak reserved memory。
  • 让长序列训练更不容易 OOM。

PPT 里给了使用方式：把 HuggingFace 的模型类替换成 Liger 的模型类。

from transformers import AutoModelForCausalLM
model = AutoModelForCausalLM.from_pretrained("/path/to/model")

from liger_kernel.transformers import AutoLigerKernelForCausalLM
model = AutoLigerKernelForCausalLM.from_pretrained("path/to/some/model")

图里还显示：在更长 seq len 下，普通 HuggingFace 实现更容易 OOM，而 Liger Kernel 仍然能跑，并且吞吐量更高。

# Quantization

量化是有损压缩。

原来模型权重可能是 32 bit 浮点数，量化后用更少 bit 表示：

  • 8 bit，也就是 int8。
  • 4 bit。
  • 2 bit。
  • 1 bit。

推理时再做 dequantization，把低 bit 表示还原到可计算的近似值。

常见量化工具 / 方法：

  • GPTQ。
  • AWQ。
  • GGML family。
  • BitsAndBytes。

注意：有些算法不会压缩整个 LLM，而是只压缩其中一部分，以换取更好的精度。

PPT 例子：

Meta-Llama-3.1-8B-Instruct-Q8_0.gguf

8B 模型如果每个 weight 用 8 bit：

[
8B \times 8\text{ bit}=8\text{GB}
]

所以只看权重，大概需要 8GB GPU RAM。PPT 里写 T4 GPU 约 15GB VRAM 可以放下这个量化模型。

量化的本质权衡：

  • bit 越低，显存越省、推理越容易部署。
  • bit 越低，信息损失越大，模型效果可能下降。

# lecture 9

这节主要讲两件事：

  1. Model Compression（模型压缩）：模型已经训练好了，怎么让它推理更便宜、更快、更省显存。
  2. Data/Parameter-Efficient Fine-tuning（数据高效 / 参数高效微调）：下游任务数据少、模型又太大时，怎么用更少数据和更少参数适配任务。

背景是：现在 NLP 系统已经大规模部署，训练大模型很贵，但推理可能更贵。因为训练是一次性的，而推理是每个用户、每次请求都要付成本。

同时，顶尖 NLP 模型并没有变小，反而越来越大。问题就变成：

如何在不牺牲太多性能的情况下，更便宜、更高效、更公平地部署 NLP 系统？

# Model Compression

模型压缩主要有三条路线：

方法 核心思想 改了什么
Quantization（量化） 模型结构不变，用更少 bit 表示参数 参数精度
Pruning（剪枝） 删除或置零模型中不重要的部分 参数 / 结构
Distillation（蒸馏） 训练一个小模型模仿大模型 重新训练学生模型

为什么压缩有可能成立？

一个原因是大模型通常是 overparameterized（过参数化） 的。参数很多会让优化更容易，但最终并不是所有参数都同等重要，所以可以压缩掉一部分冗余。

# Quantization

量化的目标是：保持模型结构基本不变，但用更低精度保存和计算参数。

比如原来权重是 fp32：

[
32\text{ bit} = 4\text{ bytes}
]

量化后可能变成 fp16、bf16、int8、int4，甚至二值化。

# Post-Training Quantization

Post-Training Quantization（PTQ）就是：

  1. 先用正常精度训练模型。
  2. 训练完后再把权重量化。

例如先训练一个 65B 参数模型，然后把权重从高精度变成 int8 或 int4。

优点：不需要重新训练完整模型，成本较低。

缺点：量化会带来误差，精度可能下降。

# 浮点数表示

浮点数一般可以写成：

[
(-1)^s M 2^E
]

其中：

  • (s)：sign bit，符号位。
  • (M)：fractional part，尾数 / 有效数字。
  • (E)：exponential part，指数部分，通常是 exp - bias。

低精度浮点数就是减少这些部分的 bit 数。这样显存更省，但表示范围或精度会变差。

# Int8 Quantization

PPT 中介绍了 absmax quantization。

核心是把一组实数线性缩放到 int8 可表示的范围：

[
[-127,127]
]

如果一组数中绝对值最大的数是 (m)，那么可以做：

[
x_{\text{int8}}=\text{round}\left(\frac{127}{m}x\right)
]

PPT 例子：

[0.5, 20, -0.0001, -0.01, -0.1]

最大值是 20，所以：

round(127/20 * [0.5, 20, -0.0001, -0.01, -0.1])
= [3, 127, 0, 0, -1]

直觉：最大的数被映射到 127，其余数按比例缩放。

问题：非常小的数可能被 round 成 0，信息会丢失。

# Binarized Neural Networks

二值神经网络是极端量化：

  • 权重只有 (-1) 或 (1)。
  • activation 也可以二值化。

这样模型非常省空间，计算也可以很快，但表达能力和训练稳定性会受影响。

在 Quantization-Aware Training 中，二值化甚至可以参与训练：

  • forward 用离散值。
  • activation 也用随机方式二值化。
  • backward 也要处理离散化带来的梯度问题。

# Model-Aware Quantization

简单统一量化的问题是：它不考虑模型内部不同权重的重要性和分布。

Model-Aware Quantization 会利用模型权重的统计规律。

# GOBO

GOBO 的观察：

  • BERT 每一层的权重大致服从 Gaussian 分布。
  • 大多数权重集中在分布主体。
  • 只有很少一部分权重位于尾部。

做法：

  • 把分布主体中的 99.9% 权重量化到 8 个 bucket。
  • 尾部的少量重要权重不量化。

直觉：大部分普通权重可以粗糙表示，但极端值可能很重要，保留高精度更稳。

# LLM.int8

LLM.int8 的问题背景：

  • Transformer LLM 中约 95% 的参数计算来自矩阵乘法。
  • 如果每层都统一量化，可能会被 outlier 干扰。

LLM.int8 的目标是让超大模型能在单 GPU 上推理。

PPT 中的结论：

  • 对小于 6.7B 的模型，量化 overhead 可能让速度变慢。
  • 但它可以让 175B 级别模型在单 GPU 上推理，并且更省时间。

量化不能只看算法，还要看硬件是否支持。

比如：

  • 很多硬件不支持奇怪的数据类型，如 int3。
  • PyTorch 也只支持一部分数据类型，例如没有原生完整支持 int4。
  • 某些量化方法需要专门写硬件加速器或 custom kernel。

所以实际部署时，量化方法必须和硬件、框架、kernel 支持一起考虑。

# Quantization-Aware Training

Quantization-Aware Training（QAT）不是训练后再量化，而是在训练过程中就让模型“意识到”低精度。

PTQ：

高精度训练完，再压低精度。

QAT：

训练时就模拟低精度，让模型适应量化误差。

优点：精度通常比 PTQ 更稳。

缺点：训练成本更高。

# ZeroQuant

ZeroQuant 是一种 layer-by-layer quantization-aware distillation。

做法：

  1. 初始化一个和原模型结构相同的量化网络。
  2. 对每一层，让量化网络模仿 full-precision 模型对应层的输出。

这样不是只在最终输出上对齐，而是逐层对齐，能减少量化误差的累积。

# Q-LoRA

Q-LoRA 是把量化和参数高效微调结合起来。

它进一步压缩训练显存：

  • 把基础模型做 4-bit quantization。
  • 用 GPU memory paging 防止 OOM。
  • 在量化模型上加 LoRA 参数，只训练很小的低秩增量。

PPT 里强调：Q-LoRA 可以在 48GB GPU 上训练 65B 模型。

直觉：

  • base model：冻结，4-bit 保存，省显存。
  • LoRA adapter：可训练，参数少。

# Pruning

剪枝是在模型训练后，删除或置零一部分参数。

和量化的区别：

方法 参数数量 参数值
Quantization 参数还在 精度变低
Pruning 一部分参数被删掉或置零 剩下的参数值通常不变

# Magnitude Pruning

Magnitude Pruning 的规则很简单：

把绝对值最小的 (X%) 参数置零。

原因是权重绝对值小，通常被认为对输出影响小。

这是 unstructured pruning（非结构化剪枝）：

  • 不关心参数属于哪个 head、layer 或 hidden dimension。
  • 只看单个权重大小。

# Lottery Ticket Hypothesis

Lottery Ticket Hypothesis 的核心观点：

在一个随机初始化的大网络中，存在一些较小的子网络。只训练这些子网络，可能比训练完整随机初始化网络更好。

这些子网络被叫做 winning tickets。

它说明：大模型里可能天然存在高效的小结构，剪枝不一定只是“删废物”，也可能是在寻找更好的子网络。

# Wanda

Wanda 是一种面向大模型的剪枝方法。

<img src="/assets/图片/image-20260428104530930.png" alt="image-20260428104530930" style="zoom: 33%;" />

它不只看权重大小，还会结合 activation 信息。直觉上，一个权重是否重要，不只取决于它自己大不大，也取决于它连接的输入 activation 是否常用、是否重要。

可以粗略理解为：

[
\text{importance} \approx |w|\cdot |x|
]

权重大且对应 activation 重要的连接，更不应该被剪掉。

# 非结构化剪枝的问题

非结构化稀疏不一定真的带来速度提升。原因：

  • 参数虽然很多变成 0，但矩阵形状没变。
  • 普通 GPU 的 dense matrix multiplication 不会自动因为很多 0 就变快。
  • 需要支持 sparse data structure 和 sparse multiplication 的硬件 / kernel。

所以非结构化剪枝可能减少参数量，但不一定减少真实推理时间。

# Structured Pruning

Structured Pruning（结构化剪枝）不是删零散权重，而是删完整组件。例如：

  • 删除整个 attention head。
  • 删除 FFN 中某些 hidden dimensions。
  • 删除某些 layer 或 module。

<img src="/assets/图片/image-20260428105127508.png" alt="image-20260428105127508" style="zoom:33%;" />

优点：删掉的是完整结构，硬件更容易加速。

缺点：粒度更粗，剪错了影响更大。

# Coarse-to-Fine Structured Pruning

这是由粗到细的Pruning。

Transformer layer 通常由两大块组成：

  • self-attention。
  • feed-forward network。

Coarse-to-Fine Structured Pruning 的思路是学习 mask，控制哪些组件关闭。

两种粒度：

  • Coarse masks：关掉整个 self-attention 或 feed-forward component。
  • Fine masks：关掉某些 attention heads 或 hidden state dimensions。

这样先粗后细，能在较大结构和细粒度结构之间平衡。

# Distillation

Knowledge Distillation（知识蒸馏）是：

训练一个 student model，让它模仿 teacher model 的行为。

通常 teacher 是大模型，student 是小模型。和量化、剪枝对比：

方法 发生了什么
Quantization 参数还在，只是精度变低
Pruning 一部分参数变成 0 或被删掉
Distillation student 的几乎所有参数都会重新学习

蒸馏和弱监督（ Weak Supervision ）关系很近。

Pseudo-label（伪标签） 是模型给无标注数据生成的标签。之后我们把这些伪标签当作真实标签来训练。

这个思想很早就有，比如：

  • Self-training。
  • Co-training。
  • Meta Pseudo Labels。想办法生成规则来打标签。

在 LLM 时代，很多 synthetic data / instruction tuning 也可以看成更复杂的 pseudo-label 生成。

# Hard Targets 和 Soft Targets

普通监督学习通常用 hard target。

<img src="/assets/图片/image-20260428112213736.png" alt="image-20260428112213736" style="zoom:33%;" />

例如三分类：

真实标签 = [0, 1, 0]

它只告诉模型正确类别是什么。

蒸馏更常用 soft target：

teacher 输出 = [0.05, 0.80, 0.15]

soft target 不只告诉 student 正确答案，还告诉它 teacher 对其他类别的相对判断。

这包含了更多“暗知识”：

  • 哪些错误类别比较像正确类别。
  • 哪些类别几乎不可能。
  • teacher 的决策边界更平滑。

# Born Again Neural Networks

Born Again Neural Networks 的有趣点是：student 不一定比 teacher 小。

它可以训练一个和 teacher 架构一样的 student，让 student 学 teacher 的 soft targets。有时候 student 甚至能超过 teacher。

这说明蒸馏不只是压缩，也可能是一种训练正则化。

# Sequence-Level Distillation

对于序列生成任务，只做单步 soft target 还不够，因为输出是整个序列。

两种做法：

1. Word-level distillation

每个时间步都让 student 匹配 teacher 的词分布。

也就是：

[
P_{\text{student}}(y_t \mid y_{<t},x)
]

去模仿：

[
P_{\text{teacher}}(y_t \mid y_{<t},x)
]

2. Sequence-level distillation

先让 teacher 生成完整输出序列，然后 student 最大化这个 teacher-generated output 的概率。

直觉：teacher 先给出“标准答案”，student 再学习生成这条答案。

Word-level：“老师每一步怎么选词，你都要学”

Sequence-level：“老师最终写了一整句话，你直接背下来”

# DistilBERT

DistilBERT 是 BERT 的蒸馏版本。特点：

  • 层数约为 BERT 的一半。
  • 参数量约为 BERT 的 60%。

技巧：

  • 用 BERT 的交替层初始化 DistilBERT。
  • 同时使用 supervised loss 和 distillation loss。
  • PPT 里提到 supervised loss 帮助不大。
  • 加入 teacher 和 student hidden states 的 cosine similarity loss。

所以 DistilBERT 不只是模仿最终分类结果，还会让中间表示也接近 teacher。

# Self-Instruct 和 Synthetic Data

Self-Instruct 的思路：

用语言模型自己合成指令和答案，再用这些合成数据训练模型学会 follow instructions。

这也是一种蒸馏 / 自训练：

  • teacher 生成 instruction data。
  • student 在这些 pseudo-labeled instruction data 上训练。

后面的 Prompt2Model、Synthetic Data Generation Toolkit 也是类似方向：用大模型或提示方法生成数据，再训练更小、更专门的模型。

# Data-Efficient Fine-tuning

预训练语言模型（PLM）面临两个问题：

问题 1：下游任务标注数据少。

每个任务都拿到大量人工标注数据并不现实。

问题 2：PLM 太大，而且还在变大。

如果每个下游任务都保存一份完整 fine-tuned 模型，成本很高。

例如 BERT-base 有 110M 参数，如果 4 个任务都全量 fine-tune，就要保存 4 份 110M 参数。

# Parameter-Efficient Fine-tuning

Parameter-Efficient Fine-tuning（PEFT）的目标是：

冻结大部分预训练模型，只为每个任务训练少量 task-specific parameters。

原模型 hidden representation 是：

[
h
]

微调后的表示可以写成：

[
h'=h+\Delta h
]

其中 (\Delta h) 由少量新增参数产生。

直觉：不要改整个大模型，只学一个小的“任务增量”。

# Adapter

Adapter 是 PEFT 的经典方法。

做法是在 Transformer layer 内部插入小模块：

hidden representation h
        ↓
down-project
        ↓
nonlinearity
        ↓
up-project
        ↓
加回原表示

也就是：

[
h'=h+\Delta h
]

训练时：

  • 原 Transformer 参数冻结。
  • 只更新 Adapter 参数。

优点：

  • 每个任务只需要存一小份 Adapter。
  • 原模型可以共享。

缺点：

  • 推理时多了额外模块，可能有一点延迟。

# LoRA

LoRA 全称是 Low-Rank Adaptation。

它的核心思想是：不要直接更新原来的大矩阵 (W)，而是给它加一个低秩增量：

[
W' = W + \Delta W
]

其中：

[
\Delta W = BA
]

如果原矩阵很大，比如：

[
W \in \mathbbR}({d_{\text{out)}\times d_{\text{in}}}
]

LoRA 用两个小矩阵：

[
A \in \mathbbR}({r\times d_{\text{in)}},\quad B \in \mathbbR}({d_{\text{out)}\times r}
]

其中 (r) 很小。

参数量从：

[
d_{\text{out}}\times d_{\text{in}}
]

变成：

[
r(d_{\text{out}}+d_{\text{in}})
]

训练时：

  • 冻结原始 (W)。
  • 只训练 (A,B)。

直觉：任务适配需要的变化可能本来就是低秩的，所以不必更新整个大矩阵。

# Prefix Tuning 和 Prompt Tuning

这两类方法都冻结 Transformer 主体参数，优化 prompt 相关参数。

Prompt Tuning

只优化输入层的 soft prompt embedding。

注意这里优化的不是自然语言词本身，而是一组可训练向量。

Prefix Tuning

优化每一层的 prefix 表示，相当于在每层 attention 前都加一段可训练上下文。

区别：

方法 优化哪里
Prompt Tuning 只优化 embedding layer 的 prompt 向量
Prefix Tuning 优化所有层的 prefix

# Prompt Tuning 做分类

标准 fine-tuning 做分类通常是：

[CLS] Premise [SEP] Hypothesis
        ↓
BERT
        ↓
Classifier Head

Prompt tuning 会把任务改造成完形填空：

Premise ? [MASK], Hypothesis

然后用 LM Head 预测 [MASK]。

比如自然语言推理中，可以把 label 映射成 verbalizer：

  • entailment -> yes / true。
  • neutral -> maybe / inconclusive。
  • contradiction -> no / false。

优点：

  • 复用预训练时的 MLM 形式。
  • 在数据很少时可以注入人工设计的任务知识。
  • 可能不需要新增分类头。

PPT 中强调：在数据稀缺时，prompt tuning 往往更好，因为它：

  • incorporates human knowledge。
  • introduces no new parameters。

# PEFT 的好处

Benefit 1：大幅减少 task-specific parameters。

多个任务共享同一个大模型，每个任务只保存少量 Adapter / LoRA / prompt 参数。

Benefit 2：不容易在训练数据上过拟合，OOD 表现可能更好。

因为可训练参数少，模型不太容易把小训练集记死。

Benefit 3：适合小数据训练。

下游数据很少时，更新全部参数风险很高；只调少量参数更稳定。

# Early Exit

Early Exit 是另一种提高推理效率的方法。

做法：

  • 在每一层或若干层后面加 classifier head。
  • 推理时不一定跑完整个模型。
  • 如果中间某层已经足够 confident，就提前输出。

例如输入：

This movie is crap ...

模型经过前几层后，如果分类器已经很确定是负面情感，就不用继续跑后面的 Transformer layer。

优点：

  • 减少平均推理时间。
  • 简单样本可以早退出。

# Semi-supervised Learning

半监督学习的设定：

有少量 labeled data，同时有大量 unlabeled data。

目标是利用无标注数据提升模型。

# Pattern-Exploiting Training（PET）

PET 是 prompt tuning + semi-supervised learning 的代表方法。

它把分类任务转成 cloze-style prompt，然后用 verbalizer 把 [MASK] 的词映射回类别。

例如 NLI：

Prompt 1：

Premise ? [MASK], Hypothesis

verbalizer：

yes / maybe / no

Prompt 2：

"Premise"? [MASK]. "Hypothesis"

verbalizer：

true / inconclusive / false

# PET Step 1

使用不同 prompt 和 verbalizer，在 labeled dataset 上 prompt-tune 多个 PLM。

也就是训练多个不同视角的模型。

# PET Step 2

用这些模型去预测 unlabeled dataset。

然后组合不同模型的预测，得到 soft label。

# PET Step 3

用原本无标注、现在带 soft label 的数据，训练一个带 classifier head 的 PLM。

所以 PET 的流程是：

少量标注数据
    ↓
多个 prompt/verbalizer 模型
    ↓
预测大量无标注数据
    ↓
组合成 soft labels
    ↓
训练最终分类模型

它利用了：

  • prompt 的任务知识。
  • 多 prompt 集成的稳定性。
  • 大量无标注数据。

等，里面会有垃圾文本、广告、乱码、重复内容、敏感内容、网页导航栏和低质量短文本。如果不过滤，模型会把这些噪声也学进去。盘古语料平台的思路是先做规则清洗，再用小模型快速评估数据质量，最后抽样成训练数据。 ![盘古语料建设平台](/assets/图片/ppt9_gpts/data_pipeline.png) #### SFT：从续写模型到助手模型 SFT（Supervised Fine-tuning，监督/指令微调）是 post-training 的第一步。它把数据组织成“用户输入 -> 助手输出”的格式，例如输入是 `USER: 你是谁？ AI:`，输出是“我是……”。这一步让模型学会按照人的指令回答，学会对话格式、任务格式和一些基本行为边界。简单说，预训练让模型“会说话”，SFT 让模型“像助手一样说话”。 SFT 数据不是越多越好。课件里反复强调 “Quality is all you need”。LIMA 的 Less Is More for Alignment 也说明，少量高质量、多样、干净的数据可能比大量低质量数据更有效。低质量 SFT 数据会让模型学到空洞、啰嗦、机械、逻辑混乱甚至不安全的回答风格。 SFT 数据可以来自人工标注，也可以来自知识蒸馏。比如 Alpaca、Vicuna 这类模型，就是让 ChatGPT 之类已经对齐的强模型先回答问题，再用这些回答训练学生模型。这样成本比完全人工标注低很多，但老师模型的偏差、幻觉和语言风格也可能被学生继承。 课件里提到的 ruozhiba（弱智吧）数据很有意思。它的问题看起来荒诞，但实际考察常识和语言陷阱。例如“银行卡在高压锅里煮了一晚上，为什么还是冻结状态”，模型不能把“冻结”理解成物理低温，而要知道这是银行账户状态。这类数据能提升模型处理反常识提问、隐含前提和歧义表达的能力。 还有一种 non-instructional fine-tuning。它不一定构造成明确问答，而是给模型普通句子的前半句，让模型学习续写后半句。它的思路是：很多能力本来就来自语言建模，不是所有后训练数据都要写成“请你做某事”的指令格式。对领域语言、写作风格、自然续写能力，非指令式微调也能发挥作用。 #### RLHF：让模型更符合人类偏好 SFT 能让模型像助手，但开放问题往往没有唯一标准答案。比如同一个问题，哪个回答更有帮助、更安全、更不啰嗦，只能比较偏好。RLHF（Reinforcement Learning from Human Feedback）就是让人类或奖励模型比较多个回答，然后用强化学习把模型往更受偏好的方向推。 PPO 是 RLHF 里常用的算法。普通 policy gradient 有两个主要问题：样本效率低，因为每次策略更新后都要重新采样；更新不稳定，因为步子太大可能让策略突然变坏，后面采到的数据也跟着变差。PPO 的做法是限制新旧策略的差距，通过 KL regularization 和 clip objective 控制每次更新不要太激进，同时用 mini-batch 提高数据利用率。直观理解，PPO 不是让模型大改，而是在当前行为附近稳一点地变好。 #### 训练工程：显存、并行与故障恢复 大模型训练的难点不只是 loss。参数、梯度、优化器状态、activation、反向传播中间结果都要占显存。一个千亿级模型，单卡根本放不下，必须用数据并行、模型并行、流水线并行、优化器并行、重计算、通信融合等技术。 ![模型训练中的计算流程和存储开销](/assets/图片/ppt9_gpts/training_memory.png) 课件里的盘古例子说明，真正的大模型训练是算法、数据、系统、硬件和集群调度一起解决的问题。大集群训练几十天，硬件故障、节点错误、网络错误都很正常，所以还需要定期保存 checkpoint、故障检测隔离、资源重调度和快速恢复。模型越大，工程可靠性越重要。 Codex 是预训练和后训练结合的典型例子。微软收购 GitHub 后，OpenAI 在 GPT-3 基础上使用大量代码数据继续训练，得到能根据函数名、注释、自然语言描述补全代码的 Codex。代码也是文本，但比普通语言更强调语法、结构和可执行性，所以代码预训练会明显增强程序生成能力。HumanEval 这类数据集就是用来测试模型能不能写出通过单元测试的代码。 ### 对齐之后的问题：遗忘与安全 #### 灾难性遗忘 Post-training 能让模型更符合人的使用习惯，但它也会带来副作用。课件里把它比作给模型“大脑动手术”：目标任务可能变强，但其他能力可能被破坏。这就是灾难性遗忘（Catastrophic Forgetting）。例如一个主要用英文数据预训练的模型，再用中文数据做 post-training，中文能力可能提高，但英文能力、安全拒答能力或其他通用能力可能下降。 ![灾难性遗忘示意](/assets/图片/ppt9_gpts/catastrophic_forgetting.png) 这个问题在安全上尤其麻烦。一个已经对齐好的模型，原本遇到危险请求会拒答；但如果后来用某个领域数据继续微调，而数据里没有足够安全样本，模型可能忘掉原来的拒答边界。课件中的例子是，模型原本会拒绝回答如何获取银行密码，微调后却可能开始给出攻击性建议。这里不是模型突然“想作恶”，而是训练目标把它往“尽量回答用户问题”的方向拉，却没有同时保留安全约束。 #### 缓解思路 解决思路之一是 experience replay。人在学新知识时，如果完全不复习旧知识，也会遗忘；模型也类似。训练新任务时混入一小部分旧任务数据，就能显著缓解遗忘。问题是旧数据未必总能拿到，尤其是商业模型、隐私数据或历史训练集不可访问时。 因此可以做 pseudo experience replay：让基础模型或旧模型自己生成旧任务样本，或者把新任务输入改写成旧任务风格，再用这些伪数据维持旧能力。LAMOL 的思路也是类似的：模型不仅学任务，还学会生成任务数据。当旧任务数据不可用时，让模型自己生成近似样本，在后续训练中回放。 LoRA 这类 PEFT 方法也和遗忘有关。全量微调会改动大量参数，目标任务可能学得更充分，但破坏原能力的风险也更大。LoRA 只训练低秩增量，相当于在原模型旁边加一小块可调结构，因此“学得少，也忘得少”。如果目标是低成本适配并尽量保留原模型能力，LoRA 很有价值；但如果需要强烈改变模型能力，它可能不如全量微调。 所以对齐不是一次完成的事情。模型上线后还会遇到新领域、新语言、新政策、新安全风险。每一次继续训练都可能带来遗忘和偏移，因此评测不能只看目标任务有没有变好，还要看原来的通用能力、安全能力、拒答能力和多语言能力有没有下降。 ### DeepSeek 与推理模型 #### V3：高效的大模型工程 DeepSeek 这一部分可以分两层看：一层是模型工程，另一层是推理范式。DeepSeek-V3 更偏通用非推理模型，适合规范清楚、输出形式明确的任务；DeepSeek-R1 更偏推理模型，适合路径开放、需要探索的问题。课件里把 V3 和 R1 的差异概括为：V3 的响应更像按规则执行，结果更稳定；R1 会主动探索多条路径，结果更开放，但不确定性也更高。 从架构上看，DeepSeek-V3 的一个重要特点是 MoE。传统 dense model 每个 token 都会经过几乎所有参数，而 MoE 有很多专家，每个 token 只激活其中一部分。课件里提到 671B 模型每个 token 只激活约 37B 参数，这样模型总容量很大，但单次计算量可控。它还引入共享专家和路由专家，既保留通用能力，也让不同 token 可以走不同专家。 另一个特点是 MLA（Multi-Head Latent Attention）。Transformer 推理时 KV cache 很占内存，尤其上下文变长后，缓存压力非常大。MLA 的思路是把 QKV 相关信息压到 latent space 里存储，减少 cache 开销，从而提升长上下文推理效率。MTP（Multi-Token Prediction）则让模型不只预测下一个 token，也尝试预测后面多个 token，帮助训练更有效。 DeepSeek 的工程优化还包括 FP8 量化训练、混合精度、DualPipe、专家并行、流水线并行、数据并行等。FP8 的意义是降低显存和带宽压力，但它也会带来精度风险，所以需要分组量化、提高累加精度、处理 outlier。DualPipe 的目标是减少流水线气泡，让计算和通信尽量重叠。这里可以看到，大模型性能不是单靠算法论文堆出来的，硬件利用率、通信调度、显存管理都很关键。 #### R1：用测试时计算换推理能力 推理模型的核心变化是 test-time compute。普通模型回答问题时，通常直接给答案；推理模型会在测试时花更多 token 做中间思考，比如验证、尝试不同路径、计划步骤。课件里说“深度不够，长度来凑”，意思是：如果模型一次前向的能力有限，可以让它生成更长的思考过程，用更多计算换更好的答案。 ![推理模型的基本形态](/assets/图片/ppt9_gpts/reasoning_model.png) CoT（Chain-of-Thought）是最基本的方法：让模型写出中间推理步骤。Few-shot CoT 是在 prompt 里给带推理过程的例子；zero-shot CoT 则用类似“Let's think step by step”的提示引导模型展开推理。现在推理模型做的是更长的 Long CoT，不只是两三步解释，而是可能包含检查、反思、换思路、验证答案等过程。 除了让一个答案更长，也可以让模型多试几次。Majority Vote 或 Self-consistency 的做法是同一个问题采样多个推理路径，最后投票选答案。Best-of-N 则是生成多个候选答案，再用 verifier 给分，选最高分的一个。Verifier 本身也可以是语言模型，它不一定生成答案，而是判断哪个答案更可信。 ![DeepSeek-R1-Zero 的强化学习思路](/assets/图片/ppt9_gpts/reasoning_rl.png) 推理能力还可以通过知识蒸馏得到。强推理模型生成“问题、推理过程、答案”，小模型学习这些数据，就能继承一部分推理行为。Sky-T1、s1 这类工作都属于用较少高质量推理数据蒸馏能力的方向。 DeepSeek-R1-Zero 更有代表性：它直接从 base model 出发，用强化学习按最终答案正确性给 reward。也就是说，推理过程写得是否像人类不是最重要的，最后答案对才是关键。这会让模型自己探索出一些有用行为，比如反思、验证、重新尝试，课件里称为 Aha Moment。之后的 DeepSeek-R1 又加入少量人工/模型生成的长 CoT 数据做冷启动，再进行 RL，并用更多数据做蒸馏和安全有用性优化。 ### 趋势：多模态、智能体与具身智能 #### 模型、算力和领域化 课件后半部分把大模型趋势分成几个方向看。第一是模型本身：开源通用模型快速发展，DeepSeek、LLaMA、Qwen 等模型让大模型能力不再只集中在少数闭源系统里。开源模型的价值不只是“免费可用”，更重要的是方便私有化部署、领域微调、教学研究和系统集成。比如 DeepSeek-R1 可以通过 Ollama、vLLM 等工具部署，本地部署时要考虑显卡显存、模型参数量、量化版本和推理速度。 第二是领域模型。通用大模型会越来越强，但很多行业仍然需要自己的专业模型，因为行业任务有专业术语、业务流程、合规要求和私有数据。课件里举了司法、教育、金融等例子：司法模型要能理解案由、庭审记录、裁判文书；教育模型要能结合教材知识点做问答、出题和学习导航；金融模型要能做知识问答、文本生成、风险分析，还要满足私有化和数据安全要求。也就是说，未来可能不是一个模型解决所有问题，而是通用大模型提供底座，行业模型在底座上加入专业知识和业务约束。 第三是算力。大模型能力提升离不开硬件。课件里提到 GPU 算力持续提升，例如 Blackwell、Rubin 这类架构继续提高推理性能、显存容量和互联带宽；Groq 的 LPU、Google 的 TPU Ironwood、存算一体芯片等也说明，AI 硬件不只是在做更快的 GPU，而是在围绕大模型的训练和推理特点重新设计。训练需要高吞吐和大规模并行，推理则越来越重视低延迟、高并发、长上下文和能效。 所以大模型的发展不是单线条的“模型越来越大”。模型架构、数据质量、后训练方法、硬件算力、部署工具和行业数据会一起决定最终效果。一个模型能不能真正落地，往往取决于它是否能在具体成本、具体延迟、具体安全要求下稳定工作。 #### 多模态：从文字扩展到图像、语音和视频 大模型后续发展不只是文本模型继续变大。一个方向是多模态：把图像、语音、视频、3D 点云等信息也接入模型。这样模型不只是“会说话”，还要能看、能听、能理解时间变化，甚至能生成图片、语音和视频。 课件里提到的联觉（Cheetah）属于图文交错多模态模型。它不只处理一张图片加一个问题，而是能处理复杂的图文混排指令，理解多张图之间的关系。比如用户给几张图片和一段指令，模型要找到它们之间的相似点、差异、时序或语义关联。这比普通 VQA 更接近真实场景，因为真实任务往往不是“看一张图回答一个短问题”。 ![联觉多模态大模型](/assets/图片/ppt9_gpts/multimodal_cheetah.png) Momentor 则面向视频。视频比图像更难，因为它包含时间结构。普通视频语言模型可能只做整体理解，比如“这个视频讲了什么”；但很多任务需要细粒度时间定位，比如用户问“从第几秒开始发生了某个动作”，模型要输出对应片段。Momentor 通过 Temporal Perception Module 和事件序列建模，把精确时间信息注入视觉特征，实现更细粒度的视频问答、片段定位和事件预测。 语音方向也很重要。NaturalSpeech 3 关注高质量语音合成，可以控制语速、韵律、音色。GPT-4o 代表的是更统一的实时语音交互：不再是先语音识别成文字、再让 ChatGPT 回答、最后文字转语音这么简单的流水线，而是更接近端到端地处理声音单位。这样模型可以保留笑声、语气、停顿、情绪等纯文本难以表达的信息。 图像理解和图像生成之间还有一个矛盾：理解任务需要抽象，可能丢掉细节；生成任务需要保留细节，才能还原图像。课件里提到 Auto-Encoding Morph-Tokens，就是试图用不同 token 表示理解所需的抽象语义和生成所需的完整视觉信息，从而缓解理解和生成目标冲突。 #### Agent：让模型从回答者变成调度者 另一个方向是 Agent。大模型如果只输出文本，本质上还是一个聊天系统；如果它能调用工具、规划步骤、执行子任务，它就更像一个智能体。Toolformer、GPT-4 工具调用、Coze 这类平台，都属于这个趋势。工具调用的关键是让模型知道什么时候该自己回答，什么时候该调用搜索、计算器、代码执行器、图像模型、语音模型或外部 API。 ![HuggingGPT 智能体流程](/assets/图片/ppt9_gpts/hugginggpt_agent.png) HuggingGPT 的思路很典型：大模型负责理解用户请求、拆分任务、选择 Hugging Face 上合适的小模型、组织执行顺序，最后再整合结果。比如用户要求“生成一张姿势和参考图相同的女孩读书图片，并用语音描述它”，系统需要先做姿态估计，再做姿态控图生成，再做图像描述，再做文字转语音。大模型在这里不是亲自完成每个感知任务，而是做规划和调度。 再往后是 GUI Agent、推荐系统 Agent 和具身机器人。GUI Agent 把屏幕截图作为输入，把鼠标键盘操作作为动作输出；推荐系统 Agent 可以结合用户画像、长期记忆、短期事件和上下文需求来调度推荐；具身机器人则要把视觉、语言和动作控制连接起来，在真实世界执行任务。Helix 这类 VLA（Vision-Language-Action）模型，以及 Nvidia Cosmos 这类世界模型，都指向这个方向。 #### 最后的思考：认知与感知 早期 AI 更偏认知系统，例如逻辑、程序、搜索、数据库；深度学习时代更偏感知系统，例如图像识别、语音识别、语言建模。现在很多问题来自两者没有真正协调：感知模型很会从数据里学模式，但缺乏常识、可解释性和稳健性；认知系统擅长规则和推理，但不擅长处理复杂真实世界输入。 未来的大模型可能会让大的认知模型控制许多小的感知模型，自动写代码、生成数据、训练模型、调用工具，形成更强的自我扩展能力。这个方向也带来担忧：生成式 AI 可能替代大量文本、代码、客服、设计、分析类工作的初级环节。对学习者来说，关键不只是会不会用某个模型，而是要理解模型背后的数据、训练、对齐、推理和系统能力，这样才知道它能做什么、不能做什么、为什么会错，以及如何把它接入真实任务。
