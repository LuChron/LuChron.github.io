  1. Accuracy (准确率)
  • 公式: TP+TNTP+TN+FP+FN\frac{TP + TN}{TP + TN + FP + FN}TP+TN+FP+FNTP+TN​
  • 释义: 所有样本中，预测正确的样本所占的比例。

  • 公式: TPTP+FN\frac{TP}{TP + FN}TP+FNTP​
  • 释义: 在所有实际为正例的样本中，被成功预测出来的比例。
  • 关注点: 减少漏报（找全）。侧重于“把所有真的正例都捞出来”。

  • 公式: 2⋅Precision⋅RecallPrecision+Recall2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}2⋅Precision+RecallPrecision⋅Recall​
  • 释义: 精确率和召回率的调和平均数 (Harmonic Mean)。
  • 特点: 综合考量 Precision 和 Recall，适用于需要平衡两者或两者发生冲突的场景。

对于多分类任务的指标计算 (Multiclass Evaluation)：

  1. 拆分 (Convert)：采用 One-vs-Rest (OvR) 策略，将每个类别轮流视为正例（其余合并为反例），拆解出 CCC 个标准的 2×22 \times 22×2 二分类混淆矩阵。
  2. 平均 (Average)：分别计算各矩阵的指标后求平均值（如宏平均 Macro-average 或加权平均 Weighted-average），从而得出全局评估结果。

对于平均值的算法有两种：微平均 (Micro) vs 宏平均 (Macro)

  • Micro-averaging（微平均）：先累计所有类别的 TP,FP,FNTP, FP, FNTP,FP,FN 数量再算指标。它受大样本类别主导，反映的是全局所有样本的整体准确度。
  • Macro-averaging（宏平均）：先算出各类的独立指标，再做算术平均。它平等对待每个类别（不看样本量），更能反映模型在稀有、小样本类别上的分类性能。

# 梯度下降

  • 核心思想：一种迭代优化算法。从随机初始位置出发，逆着梯度方向（下山）逐步调整参数 θ\thetaθ，直到走到损失函数 LLL 的最小值处（碗底）。
  • 学习率 (η\etaη)：控制每一步跨得有多大（梯度缩放因子）。常用取值范围：0.01 ~ 0.0001。
  • 算法流程：
    1. 初始化：随机给 θ\thetaθ 赋值。
    2. 循环迭代：
      • 计算当前梯度：∇θL\nabla_\theta L∇θ​L
      • 更新参数（向下滑行）：θ←θ−(η⋅∇θL)\theta \leftarrow \theta - (\eta \cdot \nabla_\theta L)θ←θ−(η⋅∇θ​L)
    3. 终止条件：当 θ\thetaθ 收敛（几乎不再变化）时停止循环，此时的 θ\thetaθ 即为最优解。

# 局限

  1. 未清洗数据：未处理异常值（Outliers），异常值容易对拟合直线产生极大干扰。
  2. 忽略类别特征：避开了特征编码（Encoding）步骤，仅使用了连续数值特征。
  3. 未做数据缩放：没有进行任何归一化或标准化处理。

核心概念对比：

  • 归一化 (Normalization)：将数值缩放到固定区间（通常是 0 ~ 1）。
  • 标准化 (Standardization)：转换数据使其均值为 0，标准差为 1。

在线性回归中我们用均方误差（MSE），而在二分类逻辑回归中，标准的损失函数是交叉熵损失（Cross-Entropy Loss）。

# Naive Bayes Classifier

朴素贝叶斯分类器

定位：在文档/文本分类（Document classification）任务中，朴素贝叶斯是一个极度流行且经典的 Baseline（基准/垫底保障）算法。

特点（优缺点）：

  • 优点：模型非常简单、训练和推理速度极快、而且数学可解释性强。
  • 缺点：正因为它太简单，它的准确率通常达不到当今最顶尖（State-of-the-art / SOTA）的水平。工程上通常先拿它跑出一个基础分数，用来给后面更复杂的模型（如神经网络）当对照组。

一些应用：

语种检测 (Language detection)：判断一句话是英语、中文、德语还是马来语。

垃圾邮件检测 (Spam detection)：判断邮件是垃圾邮件（Spam）还是正常邮件（Not spam）。

学科/题材分类 (Subject/genre classification)：识别一篇文章属于生物、化学、地理还是心理学。

作者身份归属 (Authorship attribution)：分析文风，预测某匿名文章是谁写的（比如是斯蒂芬·金还是丹·布朗）。

情感分析 (Sentiment analysis)：判断一段评论的态度是积极、消极、中立还是混合。

这是一个递归（Recursively）的过程，每到一个节点，计算机就会掏出以下“生存法则”进行判断：

  • 法则一：什么时候停？（触发叶子节点）

    • 条件 1：∣Dt∣=1|D_t| = 1∣Dt​∣=1，即当前节点里只剩最后 1 条数据了，没法再分了。

    • 结果：满足以上任一条件，节点 ttt 就会金盆洗手，正式收工成为叶子节点（leaf node）。

  • 法则二：不停的话怎么分？（选择测试条件）

    • 如果数据还很杂乱（既有 Yes 又有 No），那就选择一个最佳的特征和切分条件（choose test to split），把当前的大数据集 DtD_tDt​ 强行切分成更小的子集（也就是子树）。

# Bagging with Trees

Basic Idea

注：Bagging 的应用不局限于决策树 (not limited to Decision Trees)。

  • 多模型训练：利用不同的训练数据，训练多个基础模型（分类器 Classifier 或 回归器 Regressor）。
  • 结合预测结果：结合每个基础模型的预测结果，来生成最终的预测（如分类任务采用投票法，回归任务采用平均法）。
  • 核心优势：
    • 提高准确率 (Increases accuracy)
    • 降低方差 (Lowers variance) —— 有效防止模型过拟合，提高泛化能力。

数据来源：自助采样法 (Bootstrap Sampling)

核心问题：从哪里获取更多不同的训练数据？ →\rightarrow→ 采用自助采样法 (Bootstrap Sampling)。

  • 重复采样：从单一的原始训练数据集 DDD 中进行多次重复抽取。
  • 有放回的均匀抽样：

# Convolutional Neural Networks (CNNs)

# Motivation

图像数据可以表示为一个二维像素网格（two-dimensional grid of pixels）。因此，每个像素对应一个或多个数值（例如灰度值，或 RGB 三个颜色通道的数值）。

到目前为止，我们一直忽略了图像这种丰富的结构，而是通过将图像展平（flattening），把它们当作数字向量来处理，完全不考虑像素之间的空间关系（spatial relation）。

从全连接层（Fully Connected Layers）到卷积（Convolutions）

图像具有丰富的结构（Images exhibit rich structure）和平移不变性（Translational Invariance）

  • 假设我们希望在一张图像中检测一个物体。
  • 我们所采用的目标识别方法，理应不过分依赖于物体在图像中的具体位置。
    • 无论该物体出现在图像的顶部还是底部，我们都应该能够识别出它。

局部性（Locality）

  • 图像中彼此相邻的像素或特征通常具有很强的相关性。
  • 我们应该重点关注图像的局部区域。

理想的神经网络特性

  • 平移不变性（或平移同变性）： 在网络的最浅层，无论同一个图案出现在图像的任何位置，网络都应该做出相似的响应。

  • 局部性原则： 网络的最浅层应该只关注局部区域，不需要管图像中其他遥远区域的内容。

  • 深层捕捉更大范围： 随着网络向更深层推进，它应该能够捕捉到图像中更大范围、更长距离的特征（这与自然界的高级视觉机制类似）。

特征图 (Feature map)： 卷积层的输出有时被称为特征图。

感受野 (Receptive field)： 在卷积神经网络中，对于某一层中的任意元素 xxx，它的感受野是指：在前向传播过程中，所有可能影响到 xxx 计算的更前层元素的集合。

  • 注意： 感受野的范围可能会大于当前输入的实际尺寸（随着网络加深，后续层元素的感受野会逐层扩大，能看到包含更多上下文的更大图像区域）。

如上，在连续应用多次卷积操作后，我们最终得到的输出尺寸往往会比输入显著缩小（Considerably smaller）。

填充（Padding）和步长（Strided convolutions）能够让我们对输出的尺寸拥有更多的控制权。

# padding

卷积时，图像边缘和角落的像素被用到的次数远少于中心像素。

比如：角落的像素只被利用了 1~2 次，而中心像素被利用了 9 次。这会导致图像边缘的信息在提取过程中逐渐丢失。

我们可以在图像的边界外围包裹一圈额外的像素（Filler），以此来增加图像的有效尺寸。

通常情况下，我们会把这些额外添加的像素值全部设置为 0（即零填充 Zero Padding）。这样可以保护边缘像素不被抛弃。

# stride

定义： 步长（SSS）是指卷积核在输入矩阵上滑动时的步长大小（Step size）。

默认情况 (S=1S=1S=1)： 卷积核每次只移动一个像素。

增大步长 (S>1S>1S>1)： （注：行和列可以设置不同的步长值）。

  • 效果 1： 能够减小输出特征图的宽度和高度。
  • 效果 2： 要么是为了提高计算效率，要么是为了进行下采样（Downsample）。

# 池化

池化层（Pooling layers）完美兼顾了两个核心任务：

  1. 缓解卷积层对位置的过度敏感性（Mitigating the sensitivity to location）（让网络更具鲁棒性，允许图像有轻微的位移和变形）。
  2. 在空间上进行下采样（Spatially downsampling representations）（压缩特征图的宽高，减少计算量并加速感受野的扩大）。

池化操作：

  • 操作方式： 与卷积层类似，池化运算符包含一个固定形状的窗口（池化窗口 pooling window），该窗口根据设定的步长（Stride）在输入的所有区域上滑动，并在每个遍历到的位置计算出一个单一的输出值。

  • 不含参数： 必须注意，与卷积层不同，池化层不包含任何可训练参数（它内部没有卷积核权重）。

  • 计算机制（确定性）： 池化操作是确定性的（Deterministic），通常只计算池化窗口内所有元素的最大值（Maximum）**或**平均值（Average）。这两项操作分别被称为最大池化（Max-pooling）和平均池化。

在几乎所有实际案例中，最大池化（Max-pooling）都比平均池化更受欢迎。

注意不同于卷积后不同通道会相加，池化后各个通道依然互不干扰。

# motivation

传统的 CNN 或普通神经网络在面对“字数长短不一的句子”、“时间长短不同的视频或音频”这类变长序列数据时会显得无能为力，因此我们需要学习新的模型（循环神经网络 RNN ），来处理序列数据（长度不固定、有先后顺序的数据）。如自然语言处理等。

然而序列数据还有一些其他的问题。

传统网络的局限（独立性假设）： 传统网络假设每个输入都是彼此独立的，与过去或未来的输入毫无关联。例如，网络对两张连续图像的计算、输出和决策完全互不影响，模型不具备“记忆”能力。

序列数据的特征： 现实中的序列任务（如文本、音频、视频）打破了传统网络的假设，具有以下特点：

  1. 输入尺寸不固定（长度可变）
  2. 输出尺寸不固定（长度可变）
  3. 数据前后相互关联（连续的输入或输出之间存在强烈的上下文依赖，并非独立）

在反向传播中，误差每向过去倒退（回溯）一步，其梯度的计算在数学上都必须乘以网络的状态转移权重矩阵——WhhW_{hh}Whh​。

也就是说，如果要回溯 100 个时间步，就需要将 WhhW_{hh}Whh​ 连续相乘 100 次（即算 Whh100W_{hh}^{100}Whh100​）。

那么就会导致数学上极不稳定的状态：

  • 梯度爆炸 (Exploding Gradient)：如果权重矩阵 WhhW_{hh}Whh​ 的特征值大于 1，随着时间步变长，连乘结果会呈指数级剧烈膨胀，导致网络参数直接溢出、训练崩溃（出现 NaN）。

  • 梯度消失 (Vanishing Gradient)：如果权重矩阵 WhhW_{hh}Whh​ 的特征值小于 1，连乘结果会迅速衰减趋近于 0。这意味着远处的历史误差根本传不回来，RNN 就会“失去长期记忆”，无法捕捉长距离的依赖关系。

传统 RNN 存在“短视”的现实困境——其长期记忆依靠改变缓慢的模型权重来编码通用知识，而短期记忆则依赖节点间流转的短暂激活值（隐状态）。由于在沿时间反向传播（BPTT）时需要进行高频的矩阵连乘，导致梯度在长序列中呈指数级消失，使传统网络在处理长文本时无法建立远距离的上下文依赖。为了攻克这一硬伤，LSTM 模型引入了“细胞状态（Memory Cell）”这一中间类型的存储机制，完美结合并利用了两种记忆的优势，从而确保梯度能够平流通过极长的时间步而不发生消失或爆炸。

# Gated Memory Cell

门控记忆细胞

LSTM 与传统（Vanilla）RNN 的关键区别在于，LSTM 引入了对隐状态的门控（Gating）支持。

每个记忆细胞都配备了一个内部状态以及数个乘法门，用来决定信息的流向：

  • 输入门 (Input Gate)：决定当前的输入信息是否应该影响以及在多大程度上影响细胞的内部状态。
  • 遗忘门 (Forget Gate)：决定细胞的内部状态是否应该被清空/重置为 0（即忘记无用历史）。
  • 输出门 (Output Gate)：决定当前神经元的内部状态是否被允许影响、输出到当前细胞的最终输出中。

As a result of the sigmoid activation, all values of the three gates are in the range of (0, 1).

前向过程：给照片加噪（把好画变成雪花点）

AI在刚开始学习时，科学家会给它看成千上万张真实的照片（比如一只猫）。然后，系统会开始往这张照片上一步一步地添加随机的电视机雪花点（噪声）。 随着加噪的步数越来越多，原本清晰的猫咪照片会变得越来越模糊，直到最后完全变成一堆毫无规律的纯彩色雪花点。

反向过程：去噪生成（把雪花点变成新画）

扩散模型真正厉害的地方在这里。AI要学习的，就是如何把这个过程“倒过来”——它需要练就一双火眼金睛，学会怎么把一堆纯雪花点里的噪声一步步擦除，从而还原出一张清晰的画。 当它彻底学会了怎么“擦大雾”之后，你只要给它一堆随机的纯雪花点，并告诉它一句话（比如“画一只太空里的猫”），它就会凭借记忆和理解，每一步擦掉一点噪声、脑补一点细节，最后凭空创造出一张世界上从未存在过的全新图像。

# motivation

process（进程）：进程是运行在主机（Host）上的程序。

同一主机内的进程通信 (Within the same host)

如果两个进程运行在同一台主机上，它们通过进程间通信（IPC, Inter-Process Communication）机制进行交互，这一机制是由操作系统（OS）定义的。 常见的方式包括：

  • 共享内存 (Shared memory)：进程间共享一段物理内存空间，读写速度最快。

  • 消息队列 (Message queue)：消息的链接表，存放在内核中并由消息队列标识符标识。

  • 信号量 (Semaphores)：主要用于进程间的同步与互斥，控制多个进程对共享资源的访问。

  • 以及其他方式（如管道 Pipe、套接字 Socket 等）。

不同主机间的进程通信 (In different hosts)

如果进程运行在不同的主机上，它们无法直接利用操作系统的本地 IPC 机制，而是需要通过网络交换消息（Messages）来进行通信。

  • 这种通信必须遵循特定的网络协议（Protocols），通常会借助套接字（Sockets）API 来实现（例如客户端-服务器架构中的 TCP/UDP 通信）。

# addressing

进程寻址（Addressing Processes）

IP 地址是一个 32 位整数，用于在网络中唯一标识一台主机。由于同一台主机上通常有多个进程并发运行，仅靠 IP 地址无法在网络通信中准确定位该主机内部的具体进程。网络通信需要将数据准确交付给目标主机的特定程序，因此必须在 IP 地址的基础上引入额外的进程标识机制。

<img src="/assets/图片/image-20260714095532929.png" alt="image-20260714095532929" style="zoom:40%;" />

进程的唯一标识：三元组

在网络通信中，一个运行中的进程由以下三个要素共同唯一标识：

  • IP 地址（IP address）：定位特定的目标主机。
  • 传输层协议（Transport layer protocol）：指明通信使用的协议类型（例如 TCP 或 UDP）。因为同一个端口号在 TCP 和 UDP 下是可以独立存在的。
  • 端口号（Port number）：在主机内部定位特定的进程。

端口号的属性与划分

  • 数据类型：端口号是一个 16 位的整数，这意味着它的取值范围是 0 到 65535。
  • 保留端口（Well-known Ports）：其中 1 到 1023 的端口号是被保留给标准服务或常用知名网络协议使用的，普通用户程序通常无权直接占用。

常见标准端口号

  • HTTP 服务器：默认使用端口 80（用于网页浏览）。
  • SMTP 服务器：默认使用端口 25（用于电子邮件发送）。
  • SSH 服务器：默认使用端口 22（用于加密远程登录）。

端口号的分配和协调由 IANA（互联网号码分配局，Internet Assigned Numbers Authority） 统一管理，官方提供了具体的端口服务名称映射表链接供开发者查询。

DHCP

DHCP 是动态主机配置协议，用于自动为局域网内的主机分配 IP 地址、子网掩码、默认网关和 DNS 等网络参数。它基于 UDP 协议，采用客户端/服务器架构。通过发现、提供、请求和确认四个广播/单播交互阶段，DHCP 实现了 IP 地址的动态借租与回收，避免了手动配置的繁琐及 IP 冲突问题。

# Sockets

sockets是应用层进程与传输层协议之间的软件接口，在编程上表现为一组网络通信 API。进程通过套接字发送和接收消息。在网络控制边界上，应用层及其套接字调用由应用开发者控制，而套接字之下的传输层、网络层等底层协议栈则由操作系统完全控制。

C/S model：经典客户端/服务器（C/S）模型

C/S 模型中的角色行为 (In C/S model)

在客户端/服务器架构中，两端进程的启动和等待状态是不对等的：

  • 服务器进程（server process）：必须先于客户端启动，并持续运行，处于被动等待（listening）状态，准备接受来自任何客户端的连接请求或数据。
  • 客户端进程（client process）：是通信的主动发起者（initiator），它会主动向已知服务器的 IP 地址和端口号发送请求来建立通信。

黑盒视角 (Black box)

对于运行在应用层的程序（或进程）而言，整个复杂的互联网（包括路由器、交换机、复杂的硬件链路以及底层的 IP 路由机制）都被抽象为一个黑盒（black box）。开发者不需要关心数据包在网络中是如何路由和转发的，只需要简单地通过套接字（Sockets）写入或读取数据，网络栈就会自动完成消息的递交。

Two types of sockets

根据所选用的传输层协议不同，套接字编程主要分为以下两种类型，它们提供截然不同的通信服务质量：

  • TCP 套接字：提供可靠的（reliable）、面向字节流（byte stream-oriented）的通信服务。它能保证数据不丢失、不重复且按序到达，但有握手开销。
  • UDP 套接字：提供不可靠的（unreliable）、面向数据报（datagram）的通信服务。它不保证数据包是否一定送达，也不保证先后顺序，但传输速度快、延迟低、没有连接建立的开销。

# TCP

TCP 客户端与服务器的连接建立流程

  • 服务器创建欢迎套接字（Welcome Socket）：TCP 服务器启动时，首先会创建一个特定的套接字，通常被称为“欢迎套接字”或“监听套接字”（Listening Socket）。服务器将其绑定到特定端口（如图中的 80 端口），并在此被动等待客户端的连接请求。
  • 客户端发起连接（Client Connection）：TCP 客户端创建自己的套接字，并主动向服务器的 IP 地址和欢迎端口发起 TCP 三次握手，尝试建立可靠的连接。

Connection Socket

  • 独立通道的建立：当客户端成功联系到服务器并完成握手后，服务器的 TCP 协议栈不会占用原来的欢迎套接字去和该客户端传输数据。相反，服务器会创建一个全新的套接字——连接套接字（Connection Socket）。

# MQTT

MQTT（消息队列遥测传输协议，Message Queuing Telemetry Transport）

协议定义与核心模式

  • 轻量级协议（Lightweight network protocol）：MQTT 是一种开销极小、报文紧凑的轻量级网络协议，特别适合硬件资源受限的嵌入式设备以及带宽低、网络质量不稳定的环境。
  • 发布/订阅模型（Pub/Sub Model）：它彻底改变了客户端与服务器直接连接并相互知道对方存在的传统模式。在 MQTT 中，通信设备之间完全解耦，彼此不直接对话。

中心节点与路由机制

  • 代理服务器（The Broker）：系统引入了一个核心的中央服务器，称为 Broker（代理）。所有客户端都只与 Broker 建立连接。Broker 负责接收所有发布的消息，并决定将这些消息分发给谁。
  • 基于主题的路由（Topic-Based Routing）：消息的分发完全基于“主题（Topics）”。主题是一个分级的字符串（例如 home/living room/temp，代表客厅的温度）。
    • 发布者（Publish）：某个设备（如温度传感器）将数据打包，贴上该主题的标签发送给 Broker。
    • 订阅者（Subscribe）：其他客户端（如手机 App 或控制后台）向 Broker 表达对该主题的兴趣（订阅）。一旦 Broker 收到该主题的数据，就会立刻转发给所有订阅了该主题的客户端。

异步特征

  • 异步通信（Asynchronous）：由于 Broker 的存在，消息的发送者和接收者不需要同时在线或同时保持连接。发布者只管把消息丢给 Broker 即可，即便接收端当前离线，Broker 也可以根据配置将消息缓存，等接收端上线后再行分发。

Python 实现并发与并行主要有三类模型：多线程、多进程和基于事件循环的 Asyncio。在多进程并发且需要通过进程间通信（IPC）交互的环境下，开发者必须手动处理并解决生产者-消费者协调、数据竞态条件、资源分配饥饿以及线程/进程死锁等经典的同步与资源互斥问题。

# pitfalls

网络编程与并发的常见踩坑点及规范包括：服务器 bind 时不指定具体 IP 以监听所有接口；因 TCP 流式特征，需通过 JSON 或长度字段等应用层协议判断 recv 数据是否完整；调试时建议单包发送，多线程集成前需对各线程独立测试；坚决避免忙等待，应采用队列、条件变量或信号量实现挂起与唤醒；注意防范内存泄漏与网络明文风险，并在连接故障时优先排查防火墙端口策略。

# The language of cryptography

一些术语：

  • 明文 (Plaintext)：指原始形式的、未经过任何加密处理的消息。例如图中 Alice 想要发送的原始文字 "Bob, I love you. Alice"。
  • 密文 (Ciphertext)：指明文经过加密算法处理后生成的、无法直接读懂的加密消息。例如图中的 "ere, I oryh brx. dolfh"。
  • 密钥 (Key)：一串作为输入参数提供给加密或解密算法的数字或字符。算法根据不同的密钥会产生完全不同的加密结果。

加解密工作流程：

  • 加密阶段：发送方将明文和她的加密密钥 KA 作为输入传入加密算法（encryption algorithm），输出得到密文并将其在网络中传输。即使中间有窃听者（中间拿着三叉戟的恶魔角色），也只能截获无法理解的密文。
  • 解密阶段：接收方收到密文后，将其和自己的解密密钥 KB 共同输入解密算法（decryption algorithm），从而将密文还原回最初的明文。

为了在技术上更严谨地表达，密码学使用以下数学符号：

  • m：代表明文消息（plaintext message）。
  • KA(⋅)：代表使用密钥 KA 的加密算法，因此加密后的密文表示为 KA(m)。
  • KB(⋅)：代表使用密钥 KB 的解密算法。
  • 恒等式 KB(KA(m))=m：这是加解密能够成功闭环的核心数学要求，即对明文 m 进行加密后再用对应的解密算法解密，必须能够完美无损地还原出原始明文 m。

# types of crytopraghy

根据密钥的值，加密可分为两类（针对密钥本身）：

  1. 对称密钥密码学：通信双方使用相同密钥（KA=KBK_A = K_BKA​=KB​）。
  2. 非对称密钥密码学（又称公钥密码学）：通信双方使用不同密钥（KA≠KBK_A \neq K_BKA​=KB​），由公钥与私钥配对组成。

进程根据它们之间是否具有交互与协作划分为两大类：独立进程（Independent Process）**与**协作进程（Co-operating Process）：

  • 独立进程：在完全隔离的空间运行，既不影响也不受控于其他程序，具备高度安全和零交互的特性。

  • 协作进程：被设计用于同步与状态共享，具备高性能优势，但必须依靠操作系统定制的 IPC（进程间通信）机制来安全地跨越进程边界交换数据。例如 YouTube 或 WhatsApp 等多进程/多线程并发应用。

# Inter Process Communication

IPC 不仅用于独立进程间，也广泛用于同进程的不同线程间，是实现程序并行化（Parallelization）的基础。

将一个庞大的单体应用拆分为相互协作的小型任务，可以极大地简化设计并增强系统的稳定性。这种协作模式带来了四个核心的工程优势：

  • 模块化（Modularity）：将单体任务拆分为易于管理的独立进程，实现解耦。
  • 加速（Speedup）：能够并发地利用现代多核 CPU 架构，显著提升计算性能。
  • 数据共享（Data Sharing）：允许多个用户或客户端共同访问源数据。
  • 非阻塞（Non-blocking）：构建后台管道处理任务（例如打印队列处理程序），避免主线程因等待而卡死。

# Distributed Systems

分布式协作：将应用拆分为小型协作任务的设计模式可以跨多台机器执行，并同样享有模块化、加速、数据共享和非阻塞的工程优势。

跨主机通信机制：在分布式系统中，通信（通常）通过互联网进行。由于进程位于不同主机，它们必须依据特定的网络协议，通过在网络上交换消息（messages）来实现数据与状态的同步。

# Race Condition

多个线程（或进程、CPU）同时访问共享数据，最终结果取决于它们执行的先后顺序，这种情况就叫 Race Condition。

当两个或多个进程满足以下两个条件时，就会引发同步问题（Synchronization problems）：

  • 交错并发执行：它们在时间上交替或同时运行。
  • 共享可变资源：它们共同访问并试图修改同一个资源（例如同一块内存或同一个变量）。

最终结果是非确定的：

  • 多个进程或线程的执行顺序是由操作系统随机调度的，谁先谁后无法预测。**重复运行相同的程序，**可能会得到不同的结果。

为了防止大家同时乱动共享资源，需要采用“排队机制”：

  • 定义临界区（Critical Section, CS）：把代码中那些会引发竞态条件（即读写共享资源）的代码段，标记/指定为“临界区”。
  • 互斥访问：在任意时间点，只能有一个进程进入并执行临界区里的代码。其他进程如果想进入，必须在外面等待。

# Symptoms

但是并发同步可能出现以下问题：

死锁 (Deadlock)

  • 本质：进程互等资源，导致集体陷入永久阻塞。
  • 典型场景：两个或多个线程形成闭环等待。线程 A 占有资源 1 并等待资源 2，线程 B 占有资源 2 并等待资源 1，导致所有相关线程都无法继续执行。

活锁 (Livelock)

  • 本质：进程没有阻塞，但由于互相响应，导致无法取得实质进展。
  • 典型场景：通常发生在某些“死锁避免”算法设计不当时。线程发现冲突后主动释放资源并重试，但因为所有线程都在同步进行这种“退让和重试”，导致一直在空转，白白消耗 CPU。

饥饿 (Starvation)

  • 本质：系统整体运转正常，但某个特定进程长期无法获得所需资源。
  • 典型场景：在使用固定优先级调度算法时，如果高优先级的任务源源不断地到达，低优先级的任务就会在就绪队列中无限期等待。

生产者-消费者失衡 (Producer-Consumer Imbalances)

由于缓冲区（Buffer）两端处理速度不匹配引起的问题：

  • Buffer Overflow：生产速度远大于消费速度。缓冲区满后如果继续堆积，会导致内存占用过高，甚至引发系统崩溃。
  • Buffer Underflow：消费速度远大于生产速度。缓冲区长期为空，导致消费者线程频繁处于空闲状态，降低了 CPU 利用率。

# 线程同步原语 (Synchronization Mechanisms)

互斥锁 (threading.Lock)

  • 核心概念：确保同一时刻只有一个线程可以执行某段核心代码（临界区）。
  • 解决问题：防止多个线程同时修改共享变量，避免数据错乱（竞态条件）。

可重入锁/递归锁 (threading.RLock)

  • 核心概念：允许同一个线程多次获取同一把锁，而不会引发死锁。
  • 核心规则：线程必须调用相同次数的 release() 才能最终释放该锁。

条件变量 (threading.Condition)

  • 核心概念：用于线程间的复杂协同。允许一个或多个线程挂起等待，直到被另一个线程通知 (Notify) 某个条件满足。
  • 工作机制：内部包装了一个底层锁。调用 wait() 时会自动释放锁并让出 CPU；被唤醒时会重新获取锁。
  • 典型场景：生产者-消费者模型。

信号量/资源池控制 (threading.Semaphore)

  • 核心概念：用来控制同时访问特定资源的最高并发线程数量（维护一个内部计数器）。
  • 工作机制：获取资源时计数器减 1，释放资源时加 1。计数器为 0 时，后续线程阻塞。
  • 典型场景：对外部 API 请求进行限流。

事件协同 (threading.Event)

  • 核心概念：线程间的布尔状态信号灯（持有 True 或 False 状态）。
  • 核心特性：一旦有线程调用 set() 变为绿灯，后续所有调用 wait() 的线程都会瞬间直接通过，直到被显式调用 clear() 重置为红灯。
  • 典型场景：系统初始化完成后，一齐唤醒所有工作线程。
# 错误的同步方案：Busy Wait
  • 定义：线程在死循环中不间断地检查某个条件，期间既不挂起也不休眠（如 while not ready: pass）。
  • 严重后果：
    • 高 CPU 浪费：使单核 CPU 利用率瞬间飙升至 100%。
    • 线程饥饿：疯狂抢占 CPU 时间片，导致其他真正需要工作的线程无法执行。
  • 正确做法：绝对要避免，应用 Event 或 Condition 代替。
# 线程安全的数据结构 (queue 模块)
  • 定义：能够被多个并发线程安全地同时修改，而不会发生数据损坏或死锁的结构。
  • 内置优势：Python 的 queue 模块内部自带锁机制，代码更干净。
