# new关键字

# 1. 用途一：创建对象实例 (最常用)

这是 new 最核心、最常见的用法。它作为一个操作符，用于根据一个类的“蓝图”来创建一个具体的对象实例。

作用：

  1. 在内存中为新对象分配空间。
  2. 调用该类的构造函数来初始化这个对象。
  3. 返回对这个新创建对象的引用（内存地址）。

语法：
ClassName variableName = new ClassName(arguments);

示例：

// 根据 List<string> 蓝图，创建一个新的列表对象
List<string> names = new List<string>();

// 根据 Random 蓝图，创建一个新的随机数生成器对象
Random rng = new Random();

# 2. 用途二：隐藏基类成员 (方法重写中的特殊情况)

当在派生类（子类）中，你想定义一个与基类（父类）同名的方法，但又不想使用 override (重写) 时，可以使用 new 关键字。

new 在这里作为一个修饰符，明确告诉编译器：“我知道父类有这个方法，但我就是要创建一个全新的、与父类无关的版本，我是在**隐藏 (hiding)**它，而不是重写它。”

作用：

  • 在子类中创建一个与父类方法无关的同名新方法。
  • 消除编译器警告（如果不加 new 或 override，编译器会警告你可能无意中隐藏了基类成员）。

示例：

public class Animal
{
    public void MakeSound() { Console.WriteLine("动物发出声音"); }
}

public class Cat : Animal
{
    // 用 new 关键字“隐藏”了父类的 MakeSound 方法
    public new void MakeSound() { Console.WriteLine("喵喵喵"); }
}

// 调用行为取决于变量的“编译时类型”，而不是“运行时类型”
Animal myAnimal = new Cat();
myAnimal.MakeSound(); // 输出: "动物发出声音" (因为 myAnimal 类型是 Animal)

Cat myCat = new Cat();
myCat.MakeSound();    // 输出: "喵喵喵" (因为 myCat 类型是 Cat)

与 override 的关键区别：override 是多态的核心，调用的是对象的实际类型的方法。new 隐藏则不是，调用的是变量声明的类型的方法。通常应优先考虑使用 override。

# 3. 用途三：泛型中的约束 (较少见)

在泛型定义中，new() 作为一个约束，要求泛型类型参数 T 必须有一个公开的、无参数的构造函数。

作用：

  • 保证你在泛型代码中可以安全地使用 new T() 来创建该类型的实例。

语法：
where T : new()

示例：

// T 必须有一个无参数的构造函数
public class Factory<T> where T : new()
{
    public T CreateInstance()
    {
        // 因为有 new() 约束，所以这行代码是安全的
        return new T();
    }
}

# 类

# 1. 核心概念：类是“蓝图”

类 (Class) 是创建对象 (Object) 的蓝图、模板或设计图。

它定义了一类事物应该具有的 状态（数据） 和 行为（功能）。

  • 蓝图 (类): class Car

    • 状态/属性: 颜色、品牌、当前速度...
    • 行为/方法: 加速()、刹车()、鸣笛()...

  • 实体 (对象): new Car()

    • 一辆红色的法拉利（一个对象）
    • 一辆黑色的宝马（另一个对象）

每个对象都是根据同一份蓝图创建的，但它们是独立的个体，可以有各自不同的状态（比如颜色不同）。

# 2. 类的四大核心组成部分

我们用一个完整的 Person 类来贯穿讲解这四个部分。

// 这是一个完整的“人”的蓝图 (Class)
public class Person
{
    // 1. 字段 (Fields) -> 内部数据存储
    private string _socialSecurityNumber; // 私有的，外部无法直接访问

    // 2. 属性 (Properties) -> 对外暴露的数据窗口
    public string Name { get; set; }
    public int Age { get; private set; } // Age 外部只读，内部可写

    // 3. 构造函数 (Constructor) -> 对象的“出生仪式”
    public Person(string name, int age, string ssn)
    {
        Console.WriteLine("一个人正在被创建...");
        this.Name = name;
        this.Age = age;
        this._socialSecurityNumber = ssn;
    }

    // 4. 方法 (Methods) -> 对象的“行为能力”
    public void Introduce()
    {
        Console.WriteLine($"大家好，我叫 {this.Name}，今年 {this.Age} 岁了。");
    }
}
# a. 字段 (Fields) 和 属性 (Properties) —— 代表“状态”

  • 字段 (Field): 类内部的普通变量，用于存储数据。通常设为 private，以保护数据不被外部随意修改。就像人的基因，是内部核心信息。

    • private string _socialSecurityNumber;

  • 属性 (Property): “智能”的字段，是外部访问内部数据的唯一窗口。它通过 get 和 set 访问器来控制数据的读取和写入。这是封装 (Encapsulation) 思想的核心体现。

    • public string Name { get; set; }：这是自动属性，最简洁的写法，允许外部自由读写。
    • public int Age { get; private set; }：这表示 Age 属性，外部代码只能读取 (get)，但只有 Person 类内部的代码可以修改 (private set)。
# b. 构造函数 (Constructor) —— 代表“创建”
  • 当你使用 new Person(...) 时，构造函数被自动调用。
  • 它的工作是初始化对象，确保对象一被创建就处于一个有效的、有意义的状态。
  • 在我们的例子中，构造函数强制要求创建 Person 时必须提供姓名、年龄和社保号。
# c. 方法 (Methods) —— 代表“行为”
  • 方法定义了对象能做什么。
  • public void Introduce() 就是 Person 对象的一个行为能力。

# 3. 如何使用类：从蓝图到实体

// 使用 new 关键字，根据 Person 蓝图创建一个真实的对象 zhangSan
// "张三", 30, "123..." 这些参数会传递给构造函数
Person zhangSan = new Person("张三", 30, "123456789");

// zhangSan 是一个具体的对象了，我们可以和他交互
// 1. 访问他的属性
Console.WriteLine(zhangSan.Name); // 输出: 张三

// 2. 调用他的方法
zhangSan.Introduce(); // 输出: 大家好，我叫 张三，今年 30 岁了。

// 3. 尝试修改只读属性
// zhangSan.Age = 31; // 编译错误！因为 Age 的 set 是 private 的。

# 4. 类的三大支柱思想 (面向对象编程 OOP)

为什么我们要用类？因为它能帮助我们更好地组织代码，并实现这三大强大的思想：

  1. 封装 (Encapsulation)

    • 是什么：将数据（字段）和操作这些数据的方法（属性、方法）捆绑在一个单元（类）中，并对外部隐藏内部的实现细节。
    • 如何实现：通过 private 字段和 public 属性/方法。
    • 好处：保护数据安全，简化外部使用。

  2. 继承 (Inheritance)

    • 是什么：一个类（子类）可以继承另一个类（父类）的属性和方法，并可以添加自己的新功能或修改现有功能。
    • 如何实现：使用冒号 :。 public class Student : Person { ... }
    • 好处：代码重用。Student 类无需重复编写 Name, Age, Introduce 等代码。

  3. 多态 (Polymorphism)

    • 是什么：“多种形态”。允许不同类的对象对同一个消息（方法调用）做出不同的响应。
    • 如何实现：通过 virtual (在父类中标记方法可被重写) 和 override (在子类中重写方法)。
    • 好处：极大地提高了代码的灵活性和可扩展性。

# 总结：所有知识点的串联

  • 你定义一个 类 (Class) 作为蓝图。
  • 类里面有 属性 (Property) 描述状态，方法 (Method) 描述行为。
  • 构造函数 (Constructor) 负责在对象创建时进行初始化。
  • 你使用 new 关键字 来调用构造函数，从而创建一个真实的对象。
  • 依赖注入 (DI) 是一种高级的设计模式，它建议你不要在构造函数里 new 依赖，而是把依赖作为参数从外部传进来，其目的就是为了让类与类之间的关系更加松散、灵活。

类是 C# 乃至所有面向对象语言的基石。掌握了它，你就掌握了构建复杂软件系统的基础。

# 面向对象

面向对象（Object-Oriented）是一种编程范式，它将程序设计视为一系列对象的集合，这些对象可以相互作用、共同完成任务。这种方式与传统的面向过程编程不同，后者更注重步骤和函数。

  1. 封装（Encapsulation）：通过将数据（属性）和操作数据的方法（行为）绑定在一起，隐藏对象的内部实现细节，只暴露必要的接口给外部使用。这样可以保护数据不被外部直接修改，同时提供了一种安全的访问方式。

  2. 继承（Inheritance）：允许一个类（子类）继承另一个类（父类）的属性和方法。通过继承，子类可以重用父类的代码，同时可以添加新的属性和方法，或者重写父类的方法。

  3. 多态（Polymorphism）：多态允许一个接口或基类以多种形式表现。通过多态，可以实现代码的灵活性和可扩展性。昨天的重载也算多态的一种，不过是静态的（编译时确定）。

# 方法与构造函数

方法理解成定义在类中的函数，而构造函数是用于创建对象的特殊方法。它的主要目的是确保对象在首次使用之前处于有效的状态。

构造函数的名称必须与它所属的类的名称完全相同，且没有返回类型。当使用 new 关键字创建类的实例时，构造函数会自动被调用。如果没有为类定义任何构造函数，C# 编译器会自动提供一个无参数的公共构造函数（称为默认构造函数）。一旦定义了任何自定义构造函数，编译器就不会再提供默认构造函数。

eg.

using System;
namespace LineApplication
{
   class Line
   {
      private double length;   // 线条的长度
      public Line()
      {
         Console.WriteLine("对象已创建");
      }

      public void setLength( double len )
      {
         length = len;
      }
      public double getLength()
      {
         return length;
      }

      static void Main(string[] args)
      {
         Line line = new Line();    
         // 设置线条长度
         line.setLength(6.0);
         Console.WriteLine("线条的长度： {0}", line.getLength());
         Console.ReadKey();
      }
   }
}

# 1. 核心概念

构造函数是一个类中特殊的方法，它的核心任务是初始化一个新创建的对象。

当你使用 new 关键字创建一个类的实例时，构造函数会自动被调用。

它的主要工作：

  • 为对象的字段（成员变量）设置初始值。
  • 准备好对象运行所需要的资源或依赖。

# 2. 核心特征

  1. 方法名与类名完全相同。
  2. 没有返回类型（连 void 都没有）。
  3. 通常是 public 的，以便在任何地方都能创建该类的对象。

# 3. 主要类型

# a. 默认构造函数 (Default Constructor)
  • 这是一个无参数的构造函数。
  • 规则：如果你没有在类中定义任何构造函数，C# 编译器会自动为你创建一个看不见的、空的、公开的默认构造函数。
  • 一旦你定义了任何构造函数，编译器就不再自动提供默认构造函数。
public class Player
{
    // 没有写任何构造函数，但可以 new Player()
}
// var p = new Player(); // 调用了编译器自动生成的默认构造函数
# b. 带参数的构造函数
  • 这是最常用的类型，用于在创建对象时强制传入必要的初始数据。
  • 这能确保对象一“出生”就处于一个有效的、完整的状态。
public class Player
{
    public string Name { get; } // 只读属性
    public int Level { get; private set; }

    // 带参数的构造函数
    public Player(string name)
    {
        if (string.IsNullOrEmpty(name))
        {
            throw new ArgumentException("玩家必须有名字！");
        }
        Name = name; // 设置只读属性
        Level = 1;   // 设置初始等级
    }
}

// 创建对象时，必须提供名字
// var player = new Player(); // 编译错误！因为没有无参数的构造函数了。
var player = new Player("英雄1号"); // 正确，对象创建时 Name 和 Level 就被初始化了。
# c. 静态构造函数 (Static Constructor)
  • 用 static 关键字修饰。
  • 每个类最多只有一个，且不能有参数和访问修饰符。
  • 用途：用于初始化类的静态成员。
  • 调用时机：在第一次访问该类的任何成员（静态或实例）之前，由.NET运行时自动调用，且只调用一次。
public class GameConfig
{
    public static string Version { get; private set; }

    // 静态构造函数
    static GameConfig()
    {
        // 从配置文件或数据库加载版本信息
        Version = "v1.0.5"; 
        Console.WriteLine("游戏配置已初始化。"); // 这句话在整个程序生命周期中只打印一次
    }
}

# 4. 构造函数链 (: this() 和 : base())

  • : this()：调用同一个类中的其他构造函数。常用于减少代码重复。
  • : base()：调用父类 (基类) 的构造函数。在继承中非常重要。
public class Vehicle // 基类

# 接口

# 1. 核心概念：接口是“合同”或“规范”

接口 (Interface) 是一种纯粹的抽象类型，它只定义了**“应该做什么” (What)，而不关心“具体怎么做” (How)**。

可以把它理解为一份合同、规范或一份能力清单。任何类如果想“签署”这份合同，就必须实现合同中规定的所有条款（方法、属性等）。

经典比喻：

  • 接口 IDrivable (可驾驶的)：这是一份合同，规定了必须有 Start()、Stop()、Steer() 这些功能。
  • 类 Car 和 类 Boat：它们都签署了 IDrivable 这份合同（class Car : IDrivable），所以它们都必须各自实现 Start(), Stop(), Steer() 的具体方法。但汽车的实现和船的实现是完全不同的。

# 2. 为什么使用接口？（核心：解耦）

使用接口的主要目的是为了实现松散耦合 (Loose Coupling)，这带来了巨大的好处：

  1. 实现多态：允许你编写一段代码来处理任何实现了该接口的对象，而无需关心对象的具体类型。
  2. 强制统一规范：确保一组不相关的类都具有某些共同的功能，并遵循同样的方法签名。
  3. 支持依赖注入 (DI)：这是现代软件架构的基石。程序依赖于稳定的“接口合同”，而不是依赖于易变的“具体实现”。
  4. 方便单元测试：可以轻松地创建接口的“模拟”实现 (Mock Object) 来进行测试。

# 3. 核心语法和规则

# a. 定义接口
  • 使用 interface 关键字。
  • 接口名称通常以大写字母 I 开头（例如 IComparable, IDisposable），这是一个广泛遵循的命名约定。
  • 接口成员不能有访问修饰符（如 public），因为它们默认就是公开的。
  • 接口成员不能有方法体（实现代码）。（注：C# 8.0+ 引入了“默认接口实现”，但基本用法中仍视为空方法体）
// 定义一个“可发出声音”的合同

{

    int Volume { get; }

    // 方法规范：必须有一个 MakeSound 方法
    void MakeSound();
}
# b. 实现接口
  • 类通过在类名后使用冒号 : 来实现一个或多个接口。
  • 一个类可以继承一个基类，同时实现多个接口。
  • 必须实现接口中定义的所有成员。

# 异常处理

核心作用：捕获和处理程序运行时发生的错误（异常），防止程序崩溃，保证代码健壮性。

# 1. 基本结构

try
{
    // 1. 尝试执行: 可能会出错的代码
    // 例如：int result = 10 / 0; 
}
catch (ExceptionType ex) // 2. 捕获: 如果try中发生特定类型的错误
{
    // 3. 处理: 在这里处理错误，例如记录日志
    Console.WriteLine("捕获到错误: " + ex.Message);
}
finally
{
    // 4. 最终执行: 无论是否出错，总会执行（用于资源清理）
    Console.WriteLine("清理工作完成。");
}

# 2. 关键组件

  • try: 包裹可能抛出异常的代码。
  • catch (ExceptionType ex): 如果 try 块中发生 指定类型 的异常，则执行此块。ex 对象包含错误详情。
  • finally: 无论是否发生异常，这里的代码 总是 会被执行。主要用于释放资源（如关闭文件、数据库连接）。

# 3. 核心规则与最佳实践

  1. 捕获顺序：从具体到通用
    catch (FileNotFoundException) 这种具体的异常，必须放在 catch (Exception) 这种通用的异常前面。

    try { /* ... */ }
catch (ArgumentNullException ex) { /* 处理空参数 */ } // 最具体
catch (Exception ex) { /* 处理其他所有错误 */ }      // 最通用

  2. 不要“吞噬”异常
    空的 catch {} 会隐藏问题，是危险的反模式。至少要记录日志。

  3. 正确地重新抛出异常：使用 throw;
    在 catch 块中若要将异常向上传递，请使用 throw; 而不是 throw ex;，以保留原始的错误堆栈信息，方便调试。

    catch (Exception ex)
{
    Log(ex); // 记录日志
    throw;   // 正确方式：保留原始堆栈信息
}

  4. 优先使用 using 语句进行资源管理
    对于实现了 IDisposable 的对象（如文件流、数据库连接），using 是 try-finally 的最佳替代，能自动、安全地释放资源。

    // 自动调用 myConnection.Dispose()，即使发生异常
using (var myConnection = new SqlConnection(connectionString))
{
    myConnection.Open();
    // ...
}

  5. 避免用异常控制程序流程
    异常处理有性能开销。对于可预见的逻辑判断，应使用 if-else 或 int.TryParse() 等方法，而不是依赖 try-catch。

    // 推荐
if (int.TryParse(text, out int number)) { /* ... */ }

// 不推荐
// try { int number = int.Parse(text); } catch { /* ... */ }

# C# 方法重载

# 1. 核心概念

方法重载 就是 “一个名字，多种用途”。

它允许在同一个类中定义多个同名的方法，但它们的参数列表必须不同。

# 2. 实现规则（如何让参数列表“不同”）

满足以下任意一条即可构成重载：

  • 参数个数不同
  • 参数类型不同
  • 参数顺序不同（前提是参数类型因此而不同）

# 3. 关键禁忌（什么不能算重载）

  • 仅返回值类型不同：不能构成重载。
  • 仅参数名称不同：不能构成重载。

# 4. 编译器如何选择（重载决策）

当你调用一个重载方法时，编译器会按以下顺序寻找最佳匹配：

  1. 完美匹配：寻找参数类型和数量完全一致的版本。
  2. 隐式转换匹配：如果没有完美匹配，尝试通过安全的类型转换（如 int 转 double）来寻找一个可用的版本。
  3. 编译失败：如果找不到任何匹配项，则代码无法通过编译。

# 5. 主要优点

  • 简洁性：调用者只需记住一个方法名即可处理多种数据类型（如 Console.WriteLine()）。
  • 可读性：代码意图更清晰，方法名统一。
  • 灵活性：为同一个功能提供多种方便的调用方式。

# C# 泛型 (Generics)

# 1. 核心概念

泛型，简单来说，就是类型的占位符。

它允许你在定义类、接口或方法时，不指定具体的数据类型，而是使用一个通用的类型参数（通常用 T 表示）。直到你实际使用它的时候，再明确指定这个 T 到底是什么类型（如 int, string 或自定义的类）。

这就像制作一个“万能模具”（泛型定义），你可以用它来生产各种不同材质的零件（具体类型的实例）。

// 泛型类的定义 (模具)
public class DataStore<T> 
{
    public T Data { get; set; }
}

// 泛型类的使用 (生产零件)
var stringStore = new DataStore<string>(); // T 被指定为 string
stringStore.Data = "你好，世界";

var intStore = new DataStore<int>();       // T 被指定为 int
intStore.Data = 123;

# 2. 为什么使用泛型？（三大优势）

  1. 类型安全 (Type Safety)
    编译器在编译时就能检查类型是否匹配，避免了在运行时发生意外的类型转换错误。

    // 使用泛型 List<string>
var names = new List<string>();
names.Add("张三");
// names.Add(123); // 编译错误！不能把 int 添加到 string 列表中。

// 不使用泛型 (老旧的 ArrayList)
var items = new System.Collections.ArrayList();
items.Add("张三");
items.Add(123); // 编译通过，但运行时可能出错
string name = (string)items[1]; // 运行时抛出 InvalidCastException 异常！

  2. 性能提升 (Performance)
    对于值类型（如 int, struct），泛型避免了“装箱”（boxing）和“拆箱”（unboxing）操作，这些操作会带来额外的性能开销。

  3. 代码重用 (Code Reusability)
    只需编写一次泛型代码，就可以用于任何数据类型，无需为每种类型都重写一遍逻辑。

# 3. 如何使用泛型

# a. 泛型类

定义一个可以存储任何类型数据的类。最经典的例子就是 List<T>。

public class MyStack<T>
{
    private List<T> _items = new List<T>();
    public void Push(T item) => _items.Add(item);
    public T Pop()
    {
        T item = _items[_items.Count - 1];
        _items.RemoveAt(_items.Count - 1);
        return item;
    }
}
# b. 泛型方法

定义一个可以处理任何类型参数的方法。

// 一个可以交换任何类型两个变量值的方法
public void Swap<T>(ref T a, ref T b)
{
    T temp = a;
    a = b;
    b = temp;
}

// 调用
int x = 5, y = 10;
Swap(ref x, ref y); // 此时 T 是 int

string s1 = "Hello", s2 = "World";
Swap(ref s1, ref s2); // 此时 T 是 string

# 4. 泛型约束 (Constraints)

有时，你需要确保 T 具有某些特定的能力（比如它必须是一个类，或者必须有一个无参数的构造函数）。这时就需要使用泛型约束，通过 where 关键字来指定。

作用：为泛型参数 T 添加规则，增强其功能，并提供更强的编译时检查。

// T 必须是引用类型(class), 并且必须有一个无参数的构造函数(new())
public T CreateInstance<T>() where T : class, new()
{
    return new T(); // 因为有 new() 约束，所以可以安全地调用 new T()
}

常见约束：

  • where T : class：T 必须是引用类型（类、接口、委托或数组）。
  • where T : struct：T 必须是值类型（不能是 Nullable）。
  • where T : new()：T 必须有公开的、无参数的构造函数。
  • where T : <base class name>：T 必须是指定的基类或其派生类。
  • where T : <interface name>：T 必须实现指定的接口。

# 属性

# 1. 核心概念

属性 (Property) 是 C# 中一个特殊的成员，它看起来像一个公共变量（字段），但内部其实是一对方法。它是一个类的“智能字段”，充当了访问类内部私有数据的**“看门人”**。

{ get; set; } 是定义属性的最简洁语法。

  • get：一个读取器 (Getter) 方法。当你读取属性的值时，它被调用。
  • set：一个写入器 (Setter) 方法。当你给属性赋值时，它被调用。

# 2. 为什么在类里使用它？（核心：封装）

在类中使用属性而不是直接暴露公共变量，主要有三大好处：

  1. 封装和保护数据：你可以控制对数据的访问。例如，你可以让一个属性只读，或者在赋值前进行验证。
  2. 语法简洁：使用起来像一个普通的变量，非常直观。（person.Name = "张三"; 而不是 person.setName("张三");）
  3. 灵活性：未来如果需要增加逻辑（如日志记录、数据验证），你可以在 get 或 set 中添加代码，而不需要修改所有调用它的地方。

# 3. 两种主要写法

# a. 自动实现属性 (Auto-Implemented Property)

这是最常见、最简洁的写法。当你不需要任何额外的逻辑时，就用它。

// 编译器会自动在后台为你创建一个私有的、看不见的字段来存储数据
public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

// 使用起来就像一个公共变量
Person p = new Person();
p.Name = "李四";      // 这里调用了 set 访问器
string name = p.Name; // 这里调用了 get 访问器
# b. 完整实现属性 (Full Property)

当你需要对数据的读写进行控制时（例如，数据验证），就需要这种写法。

这种写法需要你手动声明一个私有字段（通常以下划线 _ 开头）来存储数据。

public class Product
{
    private string _name; // 私有的“后备字段” (Backing Field)

    public string Name
    {
        get
        {
            // get 访问器：直接返回私有字段的值
            return _name;
        }
        set
        {
            // set 访问器：在赋值前进行检查
            if (string.IsNullOrEmpty(value))
            {
                throw new ArgumentException("产品名称不能为空！");
            }
            // 'value' 是一个特殊的关键字，代表你赋过来的值
            _name = value;
        }
    }
}

# 总结速查

类型 语法 用途
自动属性 public string Name { get; set; } 简单的数据存储，不需要额外逻辑。
完整属性 private string _name; public string Name { get{...} set{...} } 需要在读写时添加验证、计算或通知等逻辑。
只读属性 public string Id { get; } 只能在构造函数中赋值，之后无法修改。
私有set属性 public int Count { get; private set; } 外部只能读取，只有类内部可以修改。

# 依赖注入

# 1. 核心思想

依赖注入的核心思想非常简单：不要在类内部创建它所依赖的对象，而是通过外部传递（注入）给它。

经典比喻：
一个厨师（类）不应该自己去种菜、养牛（创建依赖），他只需要专注于烹饪。厨房（外部的DI容器）会把准备好的食材（依赖的实例）直接交给他。

目标： 实现控制反转 (Inversion of Control, IoC)，从而达到松散耦合 (Loose Coupling)。

<h4>2. DI解决的问题 & 带来的优势</h4>

  • 松散耦合 (Loose Coupling)：类不再依赖于具体的实现，而是依赖于抽象（接口）。这使得系统更容易修改和扩展。
  • 易于测试 (Testability)：在单元测试时，可以轻松地传入一个“假的”依赖对象（Mock Object），从而独立地测试一个类的逻辑，而不用管它依赖的真实组件。
  • 灵活性和可维护性：当需要更换一个依赖的实现时（比如日志组件从写入文件改成写入数据库），你只需要在“DI容器”中修改一处配置即可，而不需要改动任何业务代码。

# 3. DI是如何工作的？(代码对比)

# a. 没有DI (紧密耦合 - The Bad Way)
// 依赖的具体实现
public class EmailService 
{
    public void Send(string message) { /* 发送邮件... */ }
}

// 使用者
public class NotificationService
{
    private EmailService _emailService;

    public NotificationService()
    {
        // 问题所在：自己在内部创建了依赖！
        // NotificationService 和 EmailService 紧紧地绑在了一起。
        _emailService = new EmailService(); 
    }

    public void Notify(string message)
    {
        _emailService.Send(message);
    }
}
# b. 使用DI (松散耦合 - The Good Way)

第1步：依赖于接口 (抽象)

// 1. 定义一个接口（合同）
public interface IMessageService
{
    void Send(string message);
}

// 2. 具体的实现
public class EmailService : IMessageService
{
    public void Send(string message) { /* 发送邮件... */ }
}

public class SmsService : IMessageService 
{
    public void Send(string message) { /* 发送短信... */ }
}

第2步：通过构造函数注入依赖

public class NotificationService
{
    // 只依赖于接口，不关心具体是谁
    private readonly IMessageService _messageService; 

    // 关键：依赖通过构造函数从外部“注入”进来
    public NotificationService(IMessageService messageService)
    {
        _messageService = messageService;
    }

    public void Notify(string message)
    {
        _messageService.Send(message);
    }
}

# 4. 关键术语

  • 依赖注入 (DI - Dependency Injection)：这是一种设计模式，是实现IoC的具体技术手段。
  • 控制反转 (IoC - Inversion of Control)：这是一种设计原则。它将创建对象的“控制权”从类内部“反转”到了类的外部。
  • DI 容器 (Container)：一个框架或工具，它能自动地创建对象并管理它们的依赖关系。在程序启动时，你告诉容器“当需要 IMessageService 时，就提供一个 EmailService 的实例”，然后容器会帮你处理所有注入工作。 (例如：ASP.NET Core 内置的DI容器)

# 5. 注入的三种主要方式

  1. 构造函数注入 (Constructor Injection)

    • 通过构造函数传入依赖。
    • 最常用、最推荐的方式。它能保证对象在创建完成后，其所有必要的依赖都已准备就绪。

  2. 属性注入 (Property Injection)

    • 通过公共属性传入依赖。
    • 适用于可选的依赖。

  3. 方法注入 (Method Injection)

    • 依赖只在某个特定方法中被需要时，通过该方法的参数传入。

# 总结速查

问题 类自己 new 依赖 紧密耦合，难以测试
原则 控制反转 (IoC) 将创建依赖的控制权从内部“反转”到外部
模式 依赖注入 (DI) 通过构造函数等方式，将依赖从外部“注入”进来

# 异步编程

# C# 异步编程 (async/await) 核心笔记

# 1. 核心思想：不阻塞，更高效

异步编程的核心是**“不阻塞当前线程”**。

当遇到一个耗时的操作（如网络请求、文件读写、数据库查询）时，程序可以“委托”这个任务，然后立即释放当前线程去做其他工作。当耗时任务完成后，程序会回到原来的地方继续执行。

经典比喻：

  • 同步（阻塞）：你去餐厅点菜，然后就一直站在厨房门口，死死地盯着厨师做菜，直到菜做好端给你，你才离开。这期间你啥也干不了，还占着地方。
  • 异步（非阻塞）：你去餐厅点菜，拿到一个号码牌就回到座位上玩手机或聊天（线程被释放去做其他事）。当你的菜做好了（任务完成），服务员会叫你的号，你再过去取菜（代码回到await之后继续执行）。

# 2. 为什么使用异步？

  1. UI 响应性 (客户端/桌面应用)：防止用户界面（UI）因耗时操作而“冻结”或“卡死”，保持流畅的用户体验。
  2. 服务器可伸缩性 (Web/后端应用)：在等待数据库或外部API响应时，服务器线程可以被释放去处理其他用户的请求，极大地提高了服务器的吞吐量和处理能力。

# 3. 两大核心关键字

async 和 await 必须成对出现，它们是实现异步的语法糖。

  • async (修饰符)

    • 用于标记一个方法是“异步方法”。
    • 它本身不会让方法异步执行，它的唯一作用是允许你在该方法内部使用 await 关键字。
    • 就像一个“许可”，告诉你：“这个方法里可以暂停和恢复”。

  • await (操作符)

    • 这是异步的“魔法”所在。它用在一个返回 Task 或 Task<T> 的方法调用前。
    • 它告诉程序：“暂停当前方法的执行，把控制权返回给调用者。等我 await 的这个任务完成后，再回到这里从下一行代码继续执行。”

# 4. 核心语法和规则

// 这是一个典型的异步方法
public async Task<string> DownloadWebsiteContentAsync(string url)
{
    // 1. 创建一个 HttpClient 实例 (推荐使用 IHttpClientFactory 进行依赖注入)
    using (var client = new HttpClient())
    {
        Console.WriteLine("开始下载...");

        // 2. await 关键字：
        //    - 调用 GetStringAsync 这个异步方法。
        //    - 当前 DownloadWebsiteContentAsync 方法会在这里“暂停”。
        //    - 线程被释放，可以去干别的活。
        string content = await client.GetStringAsync(url);
        
        // 3. 当 GetStringAsync 完成后，代码会回到这里，并把结果赋值给 content。
        Console.WriteLine("下载完成！");

        // 4. 返回结果，因为返回类型是 Task<string>，所以直接 return string。
        return content;
    }
}

// 如何调用它
private async void StartButton_Click(object sender, EventArgs e)
{
    string data = await DownloadWebsiteContentAsync("https://www.microsoft.com");
    // 更新UI
    myTextBox.Text = data; 
}

# 5. 异步方法的返回类型

异步方法通常有三种返回类型：

  1. Task

    • 用于不返回任何值的异步方法（相当于同步方法中的 void）。
    • 表示一个“正在进行的操作”。

  2. Task<T>

    • 用于返回一个 T 类型值的异步方法（相当于同步方法中的 T，如 string 或 int）。
    • 表示一个“正在进行的操作，且操作完成后会有一个 T 类型的结果”。

  3. void (async void)

    • 强烈建议只在事件处理程序中使用（如按钮点击 Button_Click）。
    • 为什么？ async void 方法无法被 await，并且它的异常很难被捕获，容易导致程序崩溃。应尽可能避免使用它。

# 总结速查

关键字/概念 作用 简单说
async 方法修饰符 “我是一个异步方法，里面可以用 await。”
await 操作符 “在这里暂停，释放线程，等任务好了再回来。”
Task 返回类型 代表一个不返回值的异步操作。
Task<T> 返回类型 代表一个将返回 T 类型结果的异步操作。
异步 编程模型 不阻塞线程，提高程序响应性和吞吐量。
反模式 async void 危险！异常难处理。只用于事件处理程序。
反模式 .Result / .Wait() 强制阻塞异步代码，可能导致死锁。应避免使用。
